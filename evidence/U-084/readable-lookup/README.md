# U-084：读取仍可用时保留原请求入口

2026-11-09。前台接续会话的独立复核发现 `67040f8` 仍有一个恢复缺口：
原回执暂不可取得，但同主体/AU的工作读取成功且 `can_start=false` 时，
父 WorkPanel 卸载整个 WorkExecution，导致原请求查询入口消失。原 ID
仍在 sessionStorage；这不意味着尚未执行，也不应生成替代请求。

此前 PR35 的另一角色评审、15 项 DOM、HTTP 及等待浏览器场景均保留。
前台先用固定源码快照增加反例，实际得到一项 DOM RED；真实 Chrome /
HTTP / SQLite 在授权停用连接后确认工作仍可读、`can_start=false`，刷新后
原入口确实消失。原编译产物未为制造 RED 而改坏。

新差异只把原引用查询和新执行资格分开：WorkPanel 保留当前主体范围内的
查询组件；`canExecute` 单独约束新按钮。发送时原有的当前 session、工作
读取、`can_start`、版本和预算核对继续生效。实际读取拒绝/身份错配仍清除
旧内容；不改服务端授权，不释放预约、不换 ID、不自动重放。

固定后的 18 项 DOM、8 项合并浏览器检查、5 项原 HTTP/传输/重开验证通过；
npm 检查含 240 项前端测试。浏览器先覆盖真实在途403，再完成唯一原请求、
丢弃响应、停用连接、刷新、按原ID查询和下载成果，覆盖三个宽度。最初的
夹具设置 POST 漏发 Origin 被正常403拒绝，单独保留，不计为产品 RED。
见[验证及失败日志摘要](verification.json)。新场景已加入原 CI 的等待步骤。

前台既是本次发现者也是新两文件差异的实施者，不能自行称该差异已独立批准。
具体差异与复核请求在 [PR35 评论](https://github.com/illusionaireal/Union/pull/35#issuecomment-6724165089)
及在线 #38 评论109、团队消息55/56。原 PR35 已由原负责人合到 PR34，保留
该历史；本修复随完整组合交付，需另一工程角色复核及最终准确 head CI。

组合保留 PR34/35 和已独立复核的 PR36 原提交，CI 冲突仅合并双方步骤和
证据目录，没有删减检查。最终组合 Python/npm/CI 结果记录在交付 PR。
真实模型调用为0；#38原负责人和父#22、#39/#40真实验收不由此自动关闭。
