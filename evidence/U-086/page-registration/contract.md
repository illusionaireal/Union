# U086：验收必须经过原 Core 工作登记入口

2026-11-09，基线 PR61 `9d39cbf712b1f2d422cfefb4b21069106343d4ac`。
#40 原 owner DSH；codex-home 单一实施者协助评论267/269。2–4h，一个
登记、恢复、准备的完整验收入口，不另拆卡。依据 U105/U084 现有合同；
不改变产品事务、权限、schema 或调用限额。

- 两个 driver 通过实际 Core `/tasks` 表单输入目标、AI责任成员、资料引用、
  工具、原调用上限。登记缺失/禁用/拒绝不能绕过为 API start_work 或 appoint。
- 记录页面发出的唯一 start_work 原命令和动态 Work ID，核对原主体、服务、AU、
  base_version、成功回执及 Work/Member/Binding/Definition/Mandate/预算。
  不硬编码 work-exit，不选择第一项或替代 Work。
  原登记必须引用该driver已采用的connection-a/revision1；观察到另一默认连接
  或修订不能继续使用其预算派发，保留已发生登记事实并终止本次验收。
- 页面刷新后点击“查询登记原请求”，核对唯一原回执。已落盘但POST丢失仍
  只能查原ID；unknown、401/403、身份/服务变化、错回执终止，不补发新命令。
  刷新前等待该POST本身的传输观察结束；引用出现在页面上不证明事务已提交，
  不得提前刷新中止原传输、随后把暂缺回执误认为成功或另建工作。
- 登记和重开尚无attempt/step/成果/预算占用；然后只点原 Work 的“准备本轮
  执行”，核对唯一 start_attempt 命令、原回执和持久 attempt。后续既有运行
  按原动态 Work 进入。准备失败不自动重试、运行或手工结束。
- 原登记/准备请求摘要保存为验收证据；下游原模型请求、用量、取消、下载和
  重开断言保留。既存历史文件不重写。未知 token/远端派发计数不填零。
- 先执行未改 driver 的完整登记片段观察有意义 RED，再最小 GREEN。实际
  Chrome/Core HTTP/SQLite 覆盖正常、缺控件、POST丢失、错回执/身份等。
  全量 npm/Python、准确 head CI 和另一工程角色复核后采用。浏览器只用
  临时受控 host，不运行真实 driver main；模型/真实grant均零。
- 本修复不关闭真实#39/#40/#22。取消仍走API的页面链路、历史139、完整真实
  资料正文/来源/逐请求用量及远端计数另行验收；不增加真实推理、迁移或部署。
