# U-077：在线运行态契约

2026-11-08，根据用户要求处理项目/看板审查。目标：新建在线卡即使没有仓库镜像，也能由实际成员认领；CLI、MCP 与选卡器对同一在线事实作相同决定。

- `board/status/next` 默认只读在线 API。显式 `--local` 只读历史路线镜像，不能据此认领。缺少配置、超时、认证失败不能回退本地。`check/render` 保持离线。
- `claim/release/move/record` 共用一个实现。每次写前取得活动卡、实际 `user.id`、依赖和最新整数 version。其他成员已认领、未完成前置、归档卡或无效状态在 PATCH 前拒绝；本地 owner/租约/历史 WIP 不参与决定。
- 认领只对无人负责的 ready 卡，或本人已经在执行的卡生效；后者幂等返回，不偷换成员。服务提供 WIP 上限时据实时 progress/review/blocked 计数检查；当前 API 未提供时明确显示未配置，不暗用环境或主账数字。
- PATCH 必须返回 HTTP 200。409、超时或异常状态先读回当前卡，报告原写入结果待核对，不自动重试，也不撤销可能已完成的写入。
- 释放只用于已分配但尚为 ready 的卡。已经 progress/blocked/review 的工作须保留责任，使用 blocked 与交接说明；不能清除 owner/started 历史来隐藏占用。
- 完成在写前校验 scope、reviewer、note 和存在的仓库相对证据。长期路线/成熟度/验收继续由 `management/project.json` 保存；仅显式交付同步镜像，不自动双向同步。
- 不根据本地租约过期接管在线 owner；`force` 不是凭空取得他人任务控制权的通道。协调者有实际用户授权的调度另留明确记录。

验证使用回环 HTTP 服务和伪凭据：在线独有卡、本地陈旧/损坏数据、依赖/owner/WIP、409与响应丢失、无配置、CLI/MCP一致性、完成证据预检。所有测试离线，不访问真实看板。
