# AU 关系与委托契约 v1（U-027）

2026-10-28。此契约是U-028实现输入，不是已实现跨AU调用或组织派生。第一切片限定同一受信部署域中的两个已有AU；跨平台联邦与复杂多上级授权不在v1。

## 1. 不同关系分开表达

- governance_relation：治理主体、受治理AU、有效范围/版本和真实授权适配引用。现有公司可以作为外部主体；描述关系不授予上级读取/操作全部下级信息。
- delegation：一个AU把可验收事务委托给另一个AU，双方保持独立内部岗位、成员、章程与责任。
- collaboration_reference：为共同工作建立关联，用于发现/观察，不产生治理权或资源继承。

组织树可展示治理归属，委托与协作可以跨分支。v1治理归属图禁止环；共享服务和委托图可有往返，但工作依赖必须无循环。多个不同授权来源的冲突不能简单取权限并集，需要明确实际行动依据或拒绝执行。

## 2. 委托记录

| 字段 | 语义 |
| --- | --- |
| delegation_id | 宿主稳定生成；一次事务重试沿用原ID |
| issuer_au_id / receiver_au_id | 明确双方AU引用，不能依姓名匹配 |
| objective / deliverable / acceptance | 委托范围、交付物、事先约定的验收与反馈条件 |
| issuer_work_ref / receiver_work_ref | 各AU自己的工作引用及映射，不把对方任务直接写进本地依赖图 |
| authority_refs / versions | 双方各自实际授权、章程/任职/关系版本；仅引用，无私有Key |
| resource_responsibility | 调用、主机、工具和费用分别由谁承担、限额及有效资源引用 |
| data_scope / evidence_refs | 可以共享的资料与成果范围、来源、版本、完整性及使用约束 |
| status / receipts | 当前状态、消息/命令回执、时间、取消/异常及后续责任 |

每次行动绑定一个实际AU身份和有效任职，不实现同一成员同时在双方任职。相同本地ID或工具配置不表示共同成员。子AU以后也使用同一契约，不另设“子公司执行器”。

## 3. 协议与状态

这是拟实现的宿主协议命名，不是已部署工具：

1. offer：发起AU依据实际权限提交目标、验收、资源责任和数据范围；宿主持久化后产生offered回执。
2. accept/reject：承接AU检查目标、资源、能力与约束，明确接受或拒绝；接受不等于成果已验收。
3. bind_work：接受后承接方自行安排内部成员/岗位/任务，记录receiver_work_ref，进入in_progress。
4. deliver：持久保存可读取的成果引用、摘要、实际用量/未知项及回执，进入delivered。
5. review_result：发起方按事先条件接受结果，或发送revision_requested；前者为completed，后者生成明确反馈及后续工作引用。
6. cancel：未执行的委托可以在双方核对后cancelled；在途/已外部执行的副作用先进入cancel_pending，不能仅删记录。

正常状态为offered/accepted/in_progress/delivered/revision_requested/completed/rejected/cancel_pending/cancelled。传输或外部执行结果不明时另有unknown阻断标志，保留最后已确认状态与资源占用；unknown不是证明失败或可安全重做。

## 4. 幂等、恢复和资源

命令主键为 `(issuer_au_id, delegation_id, command_id)`；相同标识内容变化拒绝。消息先持久化再发送，接收方先去重再应用，回执持久后才通知。跨数据库没有单个SQLite事务，U-028需实现明确的outbox/inbox或等效恢复协议，不假定“恰好发送一次”。

重启查原命令/交付回执并恢复，不重复创建承接工作；部分成功保留双边映射和未完成责任。确认未执行后才能释放保留资源或安全重派。

父AU分配额度不创建新额度。一次实际模型请求只能向明确资源来源记账一次，共享预算的父子统计可聚合但不可重复扣款。金额如接入真实资金，使用整数最小单位与currency并独立复核；当前不借委托协议自动转账、支付或融资。

## 5. 信息与权限

双方各自验证请求来源、实际授权、目标AU、任职及版本。关系、邀请、对方成果或申请批准文字不产生权限。共享资料按data_scope显式引用，默认不传整个组织状态、全部记忆、密钥、工作包、供应商正文或宿主路径。

成果跨边界传递后仍标来源/完整性，不能把文本里的指令当治理命令。撤权/暂停阻止后续执行；未决调用先核对，旧检查点不保留过期访问权。第一版保留受信治理接管与审计。

## 6. U-028验收及后续派生/重构

- 两个已有AU完成offer→accept→内部工作→deliver→review及一次反馈，拒绝/取消各有明确回执。
- 同一消息重复到达、结果丢失、创建工作后崩溃、重启、数据范围越权、任职撤回、资源不足均有机制测试。
- 两个AU各自成员/岗位保持隔离；共享资料只在授权范围；费用未知不能记0；一笔资源不重复消费。
- 真实模型/工作区/主机验收按U-006/U-009依赖先满足，真实跨AU成果与受控替身分开。

派生U-029复用已有AU创建+本委托协议，再添加受控资源/关系安排；测试三层机制但不强迫实际公司拆分。重构U-030/031先完成责任/知识/未决执行交接，再逐项支持拆分/合并/归属调整。跨AU成员转移需终止旧有效归属、处理在途责任后再启用新归属，不形成同时双重任职。
