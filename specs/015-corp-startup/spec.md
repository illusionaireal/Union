# 015：ai-union-corp 筹建与持久运行入口

用户于 2026-10-20 要求启动负责建设和运营 AI-UNION、ai-union-platform 的公司。本迭代完成可用条件下的筹建准备和真实工作台启动，不把缺少模型/主机/开发工具时的配置成功写成公司自主运营。

## 需求

- 公司目标和阶段章程单独保存；保持用户确认的组织/平台边界，不预写团队、岗位或业务流程。
- 使用正式 Console 创建链路和稳定请求 ID；重复准备接续原公司，不覆盖章程、资源、凭据或未知创建。
- 状态检查是只读操作，可以与已运行的工作台并行，不能用检查偷偷测试模型。
- 区分连接配置、同一连接版本的真实工具往返和实际组织交付；检查结果不暴露 key。
- 提供不启用 fixture 的正式 React 工作台入口；创建后保持原有暂停状态，不自动消费预算。
- 提供持久 Linux 主机的运行入口与 systemd 模板。累计资源和未知执行仍由既有 Engine 管理；额度到限、暂停、失败均停止自动重启；不自动充值、重置调用或核销未知结果。
- 明示当前成员仍无真实仓库读写、测试和运维工具。该缺口必须在公司自行开发/运营产品验收前解决；当前宿主工程代理开发不冒充成员工具能力。

## 验收

1. prepare 重复执行只得到一个组织；修改参数、未知创建不能悄悄创建第二家公司。
2. status 不调用模型、不改状态；启动中的 Console 不阻止读取。
3. 保存的 key 不出现在检查结果；回环替身探测不算真实，旧连接版本的验证不沿用到新版本。
4. 服务无显式有限费用接受不能调用；到限或未知执行时不重复请求、不重置资源。
5. 工作台实际提供 React 与受信会话，未启动模型时 source=not_run、成员=0。
6. 没有持久主机安装、重启恢复和成员开发工具证据时，不声称常驻经营或公司验收完成。

本迭代不修改资金或岗位授权机制，不合并 dev 到 main，不升级付费套餐，不创建法律实体。
