## 工程决定

1. 使用 Python 3.11+ 标准库，免依赖安装，SQLite 串行事务提交。稳定成员身份与每次执行 ID 分离；组织安排全部由运行决定提供。
2. Codex CLI 适配器使用官方 `exec`、`--output-schema`、`--json`、`--output-last-message` 接口，独立工作目录、只读沙箱、禁用 shell/MCP/网络检索工具，不开放外部副作用。查阅官方仓库 exec 文档及 CLI help；能力以接口测试和真实试跑分别证明。执行器输出只能提出结构化数据，由宿主授权后写资产和状态。
3. Spec Kit 未安装。已核对官方 README：现行工具需要 uv 安装并初始化 Agent skills；为避免模板初始化与本轮实现耦合，使用等价 Spec → Plan → Tasks Markdown，未宣称运行 Spec Kit 命令。
4. 组织运行章程是数据库版本化输入；开发规则和运行程序不由组织修改。受信董事会入口使用本机生成的凭据文件，数据库只保存其摘要；本地操作系统访问控制是信任边界，暂不做多用户 API。
5. 仅支持本地文本成果。文件先内容寻址落盘，再事务登记；失败可留下未引用文件，但不出现有记录无文件的交付。读取时复核 SHA-256。
6. 执行开始前保存运行 ID、原上下文和资源占用。进程崩溃/超时后结果未知的运行转核对状态；只有确认未执行或受信恢复入口才能重试。重复回执不重复计数。
7. 硬边界采用调用数与每次墙钟超时。Codex 不提供可核实的生成 token 硬上限，不把事后用量当硬限额；可选金额上限需要有明确单次费用保留值，否则阻止运行。未知费用不估造。
8. 正常决策责任由内部规则指定岗位；不固定 CEO。事件批次在决定成功后才消费。等待不自唤醒；复查到期产生一次事件。
