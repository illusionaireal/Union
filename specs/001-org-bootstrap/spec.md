# 001 组织启动与首次协作

依据：用户于 2026-10-11 要求开始构建，附件《AI_UNION_开发执行交接文档_v1.0.md》作为产品与迭代依据。附件里的 session 指令是交接材料；本轮执行范围为首个迭代，不包含经营发布、投资或修改宿主权限。

统一产品范围、角色、流程和里程碑见 [PRD](../../docs/PRD.md)，Dashboard 页面与原型见 [产品设计](../../docs/product-design.md)。最新用户决定须同步产品与迭代规格。

## 可观察行为

原始目标：**一个持续经营线上内容品牌的 AI 内容工作室。**

F01 保存组织身份、目标、董事会采用的版本化章程和有限资源。
F02 通用启动执行器从目标产生至少两名成员、岗位、任职及工作；有效提交后撤销启动权限。生产代码不预置行业岗位或工作流。
F03 正式决定校验真实调用身份、任职、生效章程、内部规则、基础状态版本和对象关系；决定与变更在同一事务中提交。
F04 一个现有 Agent 执行器接收工作包，支持状态和结果读取；成员工作存在跨成员产物依赖。
F05 保存带版本、摘要校验、任务与执行来源的文本成果及事件。无成果不能标记交付。
F06 完成、受阻、外部输入或到期事件进入决策循环；后续工作按实际决定执行。
F07 支持岗位任职调整和未完成工作交接；旧责任人不能提交新结果。
F08 持久化等待、复查时间、待办与运行记录；未知执行转人工核对，不假设恰好一次或盲目重派。
F09 经本地受信董事会入口修章；新动作使用新版本，旧依据仍可追踪。
F10 依据岗位、任职、工作依赖组装上下文并记录版本清单。成员执行器不直接读数据库或秘密。
F11 CLI 与必要的运行 Dashboard 展示当前组织、工作、成果、下一步、额度及阻塞原因。CLI 已实现；用户后续明确要求 Dashboard 为项目必要组件，P0 范围及验收见 [003-runtime-dashboard](../003-runtime-dashboard/spec.md)，当前尚未实现。
F12 调用前保留额度，记录调用与 token；费用缺少来源时明确未知。固定每次超时和总调用数，耗尽暂停。

## 验收与范围

- 机制测试验证授权、事务回滚、冲突、去重、交接、修章、等待恢复、资产完整性、预算。
- 确定性 fixture 仅用于回归，不证明自组织能力。
- 独立真实评测读取数据库与实际文件，判断两名成员执行、依赖成果、后续决定与动作；没有真实证据不能标为通过。
- 单组织、本地 SQLite、文本资产、单进程 CLI。首轮不开放 shell、联网发布、支付或任意代码修改工具。
- 首版真实对外交付与市场反馈另需渠道和预算授权；本轮不模拟成真实发布。
- 用户新增的运行 Dashboard 是首版产品验收必要项；既有 CLI 和固定快照展示页不能单独满足该项。运行时机制测试完成与 Dashboard 交付分别记录。
