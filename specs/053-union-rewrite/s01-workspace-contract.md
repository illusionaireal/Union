# U-111：V1 组织入口与原创建恢复契约

2026-11-16，编码前冻结。父卡 U-111/#65；顺序子卡 U-125/#79、U-126/#80。
依据为 [完整体验](../../docs/product-design.md)、[前端责任](../../docs/FRONTEND.md)、
[S01 原创建协议](s01-contract.md)、ADR-0003/0004/0005/0006。
读取基线 `2b3d281f7bfb6dc3fdb8e00f432cc4f76756a8fc`，U-110/U-118 已由 PR #90 合入。
本契约细化既有体验，不替换领域、认证、创建或资源协议，不关闭完整产品父出口。

## 1. 结果与顺序

U-125 先交付固定地址登录后的合法 V1 组织列表、重开和新空间导航。
U-126 随后交付在同一入口表达组织目的、成功依据和约束，创建准备态 AU，
并在丢响应、重开后核对原创建。两项完成后贯通验收 U-111。
保存零推理、零资源授予，初始治理根仅由原 CreationService 绑定当前可信主体。
用户不搬运内部 ID、不需要旧 AU 迁移或操作 JSON；单 Agent 合法。
准备记录、有效治理、资源就绪和自主业务分开呈现。
后续资源、完整工作成果、治理交接、改进和合作仍由对应卡接续。

## 2. 路由、选择与读取

| 路径 | 解析结果 |
| --- | --- |
| `/` | 当前主体/服务下经核验的最近 V1 组织；无有效最近记录到 `/organizations` |
| `/organizations` | 仅列会话授权的 `core_v1` 目录项；不读取全部 AU，不默选首项 |
| `/au/:auId` | 组织概况 |
| `/au/:auId/work`、`/au/:auId/work/:workId` | 工作入口及指定工作 |
| `/au/:auId/results`、`/au/:auId/work/:workId/results/:resultId` | 成果入口及 AU/Work/result 完整作用域 |
| `/au/:auId/attention` | 关注与准备缺口 |
| `/au/:auId/resources` | 能力与资源 |
| `/au/:auId/governance` | 治理与成员 |
| `/au/:auId/improvement`、`/au/:auId/collaboration` | 改进、合作入口及实际支持范围 |

路径中显式 AU 优先于旧查询参数和最近记录。标识符是单个非空路径段，
沿现行公开标识符 `[A-Za-z0-9][A-Za-z0-9_.-]{0,79}`（1–80 字符），合法内部点号保留；
斜杠、反斜杠、点段、非法百分号/UTF-8、重复编码及额外路径拒绝。标识符不是显示名称。
查询参数不增加读取权；Work/result 页面须消费对应受权公开 API 才能声明实际内容。

旧 `/overview`→概况、`/tasks`→工作、`/artifacts`→成果、`/activity`→关注、
`/models`/`/resources`→资源、`/members`/`/settings`→治理；只使用旧
`organization` 明确指定且当前可读的 V1 AU 做 replace。无明确作用域回列表，
显式 legacy/未知/无权目标保留拒绝说明，绝不改读另一 AU。
旧 `/gateways` 不挂旧平台页，返回组织列表并解释新核心入口的支持范围。
未知 URL 不通用回退 HTML；服务器仅声明上述模板和原静态资产白名单，
保留 CSP、nosniff、同源检查及目录越界拒绝。

`app/workspace.tsx` 是身份、服务和 AU 选择的唯一前端 owner；App 组合路由，
Layout 仅布局/导航，不按 profile 重写页面。不调用 `/api/snapshot` 或 legacy
成果/执行入口作为 V1 回退。AU 读取须匹配 `core.au.v1`、受权主体/服务、
目录 profile 与 AU ID；目录不是治理事实。

最近访问只保存版本化 `{service_instance, principal_id, au_id}` 导航引用，
不保存名称、正文、凭据或权限，不形成第二事实缓存。实际 AU 读取成功才更新；
恢复时重验身份、目录与 AU。存储不可用时列表/深链接仍可用。
显式拒绝不隐式跳到最近组织；普通退出不撤销已合法采用的运行授权。

## 3. 异步与身份边界

同一主体/服务下切换 AU 立即隐藏上一 AU 正文和操作资格，保持账户边界稳定；
迟到的已取消请求不能改变新身份或空间。跨主体/服务立即清除受保护视图、
表单、下载与回执；同主体普通会话续期不无故丢失草稿。

401 会话失效、403 AU 拒绝、目录移除及协议/身份不匹配使旧内容不可见。
网络故障只允许同身份/服务/AU 的最后已核验快照只读显示，明确过期并禁止新写；
首次进入/跨 AU 无成功读取不能显示别的缓存。重连重读，不把旧缓存当最新权限。
拒绝后断网不能复活已清除内容。

原创建查询独立于当前 AU 可写性：有效的原主体/服务仍能核对自己的原请求。
单一回执 403 不冒充整个账户退出；失去新动作权限不抹去合法原回执。

## 4. 创建与恢复（U-126）

保留 `POST /api/commands` 五字段外层及 `kind=create_v1`，data 精确为
`name,goal,board_name,charter,resources`。目的、成功依据、约束分开表达，
用明确段落保存到现有 `goal` 文本，不新增数据库字段或第二目标对象。
章程正文、计划资源标明尚未生效；治理显示名称不授予权限。

同一次确认在 POST 前持久保存原 ID/kind、主体/服务及空组织引用；失败不 POST。
只保存恢复引用，不保存目标、章程、密码、密钥或请求 payload。
查询固定 `/api/v1/receipts?id=原ID`，不因回执已有 AU ID 改查组织命令表。
刷新、重连、unknown 只查询，不自动新建或重发 POST。成功回执打开同一 AU
的新规范 URL并重读当前目录/权限；重复或迟到结果不得覆盖已确认结果，
不得在身份/服务切换后导航或恢复敏感内容。

`service_instance` 是运行实例标识，服务正常重启也会变化。实例变化清除缓存和
旧响应资格，但新会话核验同一稳定 principal 与当前同源服务后，仍可查询原ID；
不能用旧实例永久阻断重启恢复。查询响应须绑定发起本次查询时的新实例，
中途再变更则丢弃。后端保留最终原请求授权，失败不重放POST。

旧 `union-pending` 引用保留：有主体/服务的 V1 项只在上述重验身份后自动查询；
缺字段的历史 V1 项不得猜归属，单独说明只能在原账户显式核对。
旧 legacy 项不自动读取/派发、不丢弃历史，由原受控客户端处理。
手工核对也须当前受信身份及服务端最终授权，不能只比显示名称。

## 5. 页面与可用性

列表显示当前有权目录，空态给创建入口。连接故障、缺核心身份、旧链接、无权组织
有独立说明与返回路径。概况显示实际名称/目的/准备状态及下一入口，
不虚构工作、成果、花费或自治。八个导航按对象分工；尚未贯通的子页面说明
具体缺口，不能整页挂载旧 GovernanceWorkspace 或手工控制台。
可重用范围明确的正确 feature，但不得把局部工程能力表述为完整旅程完成。

真实浏览器验证 1440/1024/768/390 四宽度；移动保留概况、工作、成果、关注，
其余经可键盘展开导航访问。正文无横向裁切；表单有标签、字段关联错误、可见焦点；
弹层开关恢复焦点，前进/后退/刷新遵从 URL。

## 6. 文件责任与验收

协调者负责契约/ADR/计划、App/Layout/workspace/组织页面及样式、命令创建恢复、
浏览器消费者迁移、统一验收、Kanban、主账、Git。可独立委派 HTTP 子工作只改
`ai_union/server.py` 静态路径匹配及定向测试；共享身份/命令/路由树顺序整合。
子代理不写账本、在线卡、Git 或真实宿主。另一工程角色独立复核身份/回执/路径。

| 检查 | 可证伪结果 |
| --- | --- |
| E01 默认进入 | 未选择无 AU 请求；legacy 首项不影响列表；最近项重验才开 |
| E02 路由 | 深链接/旧链接保持作用域；未知、编码异常、穿越、跨主体不读别的 AU |
| E03 身份 | 主体/服务/AU变化、迟到响应、401/403、拒绝后断网不泄漏旧内容 |
| E04 网络 | 同作用域断网保留标明过期快照及原引用；恢复只读；禁止新写 |
| E05 HTTP | 声明模板200/HTML/CSP；未知API、文件、穿越、未声明URL404 |
| E06 创建 | 有效RED后实现；一次创建、可信根、零推理、刷新/重启同一AU |
| E07 原请求 | 丢响应、重复确认、200拒绝、迟到失败、存储失败、换身份不重派/串回执 |
| E08 用户入口 | 四宽度、键盘/焦点、前进后退、空态、无权和实际准备缺口 |

TDD Route: strict（用户 AGENTS），行为先真实 RED，再最小 GREEN。
旧界面断言按新契约迁移；有效的原请求、权限、资源、结果完整性仍由其
API/领域/feature 测试覆盖，证据列出浏览器替换及未验边界。
固定 Node 24.19.0 `npm run check`、项目 Python UTF-8 全量、定向 HTTP、
实际浏览器及独立复核后交付 PR。受控使用不代表真实模型、完整 V1 或持续经营。

变化必要性：文档无法阻止选首项、旧路由和错误回执恢复，选择 `code-change`。
复杂度：替换原路由/作用域而非叠加第二壳；Layout收缩为导航，页面按实际责任拆分，
路径辅助纯解析，不新增存储/认证/调度 owner；server只扩明确匹配。
停止条件：需要改变持久身份/创建协议、缺可信主体、迁移/真实支出/部署，
或只能恢复第二旧UI写者才能通过时先回原契约复核，不静默扩大范围。
