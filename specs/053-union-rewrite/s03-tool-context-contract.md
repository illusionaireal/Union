## 冻结接口与事务

1. `run_step` / `run_loop` 沿原 API。每个成功模型轮次保存规范的 assistant 消息；每个工具调用保留原 ID、函数和参数，紧随配对的 tool 消息。列目录返回实际相对文件名；读文件返回已授权正文、路径、原文件 SHA-256/字节数及原工具 receipt 引用。正文伴随工具请求时属于中间轮次，不提前产生候选成果。
2. 原正文只存同一 AU SQLite 的私有 `work_model_turns` 表。GovernanceStore 仍为唯一事务写者：模型轮次、工具 receipts、step 的上下文摘要、用量和命令回执共同提交或回滚。应用负责接续，领域不导入文件/数据库；不改变 S02 私有表用途，不引入第二套运行时。
3. step 记录 `context_sha256`；私有 payload 绑定 AU/Work、Agent Definition id/version、责任 binding id/version、Mandate id/version、资料根引用。接续校验范围与摘要；丢失或篡改拒绝派发，不重读文件伪造原结果。只在显式成功命令创建表，读取不迁移；旧 schema 3 无表且无引用可正常读取，旧自动轮次缺少可恢复上下文时拒绝继续，保留原历史。
4. 每次发送资料前重新检查当前身份、有效治理、工作/执行所有权、binding/Mandate 和工具允许范围，以及原宿主资料根仍注册。返回后的工具执行再检查当前规则。一个工具批次至多 10 个、ID 在批内唯一，参数符合原工具契约；不截断批次产生不配对消息。文件仍受原大小/路径边界；完整消息总量超过 4 MiB 时明确拒绝下一次派发，不静默丢弃或重新摘要。
5. 同一 Work 的后续显式执行可在现有 stale-attempt 处置和新 attempt 授权后接续，范围/版本仍须匹配；不会自动恢复旧执行或跨 Work/AU 共享。后续成果来源包含模型实际看到的原工具 receipts，正文和私有上下文不进入工作投影、命令回执或审计快照。

## 验收与边界

编码前边界细化：资料根标识被宿主重新绑定也视为原数据访问边界变化。私有轮次保存实际解析目录的摘要，后续派发必须仍匹配；摘要和真实路径均不进入公开投影，不重新读取原文件。

modeld 返回的 `_native` assistant 上下文按原字节语义保存在私有轮次并原样接续，保留提供者推理/工具配对字段；不投影、不解释为授权。下一请求继续由 modeld 校验 AU/account/model/upstream 范围及配对，不自行合成或放宽协议。

- 有意义 RED：动态 fake 只根据接收到的工具正文/文件列表作答，验证 assistant/tool 配对、第二/三轮正文、来源与 HTTP 持久结果；不能靠预置答案证明读取资料。
- 重启并显式接班后保留原字节语义和来源，即使文件已改变；私有上下文不公开。篡改、缺失、撤权、越域/非法批次拒绝派发或读取；事务故障不留下孤立上下文。
- 原三项探针在基线均 RED；本子项只关闭工具正文项。派发前预约/并发原请求归属保持未完成；撤权事实修复仍在独立 PR #20，不能冒称已采用。未知回执不重放。
- 固定工具链定向、Python 全量、npm check；当前 CI 与另一工程角色的权限/资料边界复核后方可采用。本候选不迁移真实数据、不部署、不新增真实推理，不关闭 U-067 或真实业务验收。
