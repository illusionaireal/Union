# S03：模型派发前预约与原请求核对（编码前冻结）

2026-11-08；U-067 / PR #17。前台部署协调者接续最后一项原评审阻塞。
基线为已复核的 PR #20 与 PR #21 组合 `04905cf4de660dedb31c8cef44e953fc32845215`。
依据 Chapter D-01/D-04、R-01/R-03/R-05、K-04，沿 ADR-0005 的原请求事实与行动采用分离。
预估一个 2–4 小时工程结果；当前仅前台持有宿主执行锁，五分钟巡检继续；原 #22 owner 与真实验收未完成状态保留。

## 冻结行为

1. 每次自动模型调用先在 GovernanceStore 的同一 AU 事务提交唯一原命令、Work/Member/binding/Mandate/Agent Definition 版本、attempt、step、模型请求 ID 与一个预约，再离开账户/AU 锁调用通道。请求 ID 在 AU/原命令范围内稳定，跨 AU 不冲突。
2. 使用已有治理事实写入方式记录内部准备/观察事件，保留各自正确 base/version；外部原命令的最终回执与最终事实在同一事务保存，原回执不改写。不新增数据库写入者、读迁移或另一执行循环。
3. 重复同一命令先查原回执与已提交意图；存在未决意图时返回原 step/模型请求与待核对状态，不再 POST。相同 ID 的不同输入或不同主体仍拒绝。进程中断、存储失败和不确定网络结果均保留原预约；重启不自动再派发。
4. 同一 Work 的未决自动调用阻止该 Work 再派发；不同 Work 不因这个预约而全局串行。返回时以当前有效身份、治理、责任/授权/连接版本、attempt 与资料范围决定是否采用，不因其他独立 Work 的 AU 版本增长丢掉本次事实。
5. 已完成的模型调用总是结算原 step 为 used，并保存非负整数用量和未知费用。会话失效、治理修订、attempt 结束、非法模型工具或不能采用的输出都不能抹去调用；这些情况不保存正文或执行工具。通道明确拒绝时释放原预约，保留“预约曾存在、推理未执行”的区别。
6. 公共手工 settle 不能释放正在派发的自动预约。原请求核对只查已持久关联的 modeld ID，不调用 POST；只有确认 completed 才记录 used/usage，且核对不采用正文。缺失、授权/网络故障或未确认终态保留 unknown 与预约，不凭一次 404 推断远端永远未执行。
7. 工具正文、私有上下文、使用记录和结果仍在现有 AU 事务提交。最终保存失败时回滚本次结果/上下文，先前已提交的预约及原请求 ID 必须仍在。人工与既有 legacy 步进保留其原协议。
8. run_loop 复用 run_step；回执反映实际最新版本、已知完成次数及用量。未知或不可采用时停止，不以本地取消证明远端取消。

独立复核补充：原命令 ID 的排他跨全部 GovernanceStore 命令种类生效，不能用同 ID 的 finish_attempt/治理/模型配置抢先占回执。资料绑定在通道建立后、派发前与结果采用前再次核对；历史正文不能在宿主取消登记后再披露。核对自动调用沿用原 API 输入格式并完整校验，`status` 只是用户期望，实际执行事实取自原模型请求。手工/legacy 步进保留旧核对语义。

循环恢复补充：父循环持久保存原请求身份和初始轮次上限。本实例并发重入只返回中间态，不能抢先固化父终态；重启/父回执保存失败后先读已完成子回执，余额为零也不能丢失原结果。进程内在途集合仅判断当前是否真的有调用运行，最终保存失败退出调用后可直接查询原模型请求，不要求重启服务。

## 有界验证

先观察真实失败：派发入口的独立 SQLite 读取看到预约；同 ID 重入、同 Work 并发与其他 Work 进展；进程式中断/最终保存故障后不重放；调用中撤权、会话变化或 attempt 结束仍保留事实；明确拒绝与未知不同；原 ID 核对只有 GET、不能凭 404 释放。原三项独立探针全部应通过。

固定工具链执行受影响回归、Python 全量及 npm check；权限/计量部分交给另一工程角色复核后才合入。实现不消耗真实模型、不迁移真实 AU、不切换 NAS，也不关闭 U-067 的真实任务及持续运行出口。
