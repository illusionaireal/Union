# S03：持久派发记录的发布兼容边界（编码前冻结）

2026-11-08，U-067 / 原派发修复的兼容子项，基线 `bbe8068`。
依据 PRD F12/F20、Charter R-05/K-04 与 ADR-0005 的版本兼容决定。

跨版本探针已经在真实临时 SQLite 复现：新实现提交预约后中断，当前
安装器接受仅声明 AU schema 3 的旧候选 `90d8b1f`；旧 Console 成功把
该自动预约手工结算为 released，没有查询原模型请求。仅保留新增字段
不能保护未知占用。此探针没有使用真实模型或 NAS 数据。

## 冻结合同

- 首次显式提交自动派发或父循环准备事件时，在同一 GovernanceStore
  事务把该 AU 标为 schema 4。预约/循环身份、原事件及版本仍由原写入者
  保存；事务失败全部回滚，transport 之前已提交版本标记。拒绝准入、
  读取、普通 S02/手工工作不会自动升级。
- schema 4 继续使用现有治理、模型与责任规则；不能因增加版本而跳过
  私有模型记录校验、原请求核对或授权。后续治理/模型操作不降级版本，
  未知/已用/明确释放均保留 schema 4 与所有历史，重开不重新派发。
- React 对公开 schema 4 投影沿用当前主体、服务实例和 AU 范围校验；
  首次派发后刷新仍能读取同一 AU，版本支持不能授予或恢复访问权。
- 受支持发布器在 activate/rollback/run 前拒绝不声明 schema 4 的候选，
  不改代码指针、AU/身份数据或原请求。当前构建声明 `[1,2,3,4]`。
- 已由 PR #17 写入、尚为 schema 3 的自动预约/循环仍可原样读取和核对；
  当前发布器也要求其目标候选支持 schema 4，不靠读操作迁移这批数据。
  该旧数据必须使用更新后的发布器；任意旧安装器/二进制无法被新代码
  追溯修补，直接绕开受支持入口不在兼容保证内。
- 原 schema 1–3 无自动派发记录的数据继续兼容其受支持候选。原创建
  字节、AU/member/request ID、审计、费用未知及保留预约不改写。
