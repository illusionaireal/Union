# 017 项目管理骨架

2026-10-28。用户要求继续建设，先搭管理架子；依据前两轮讨论，把组织自我改进纳入近期目标。

## 结果

- 一个可版本化的主账记录模块、里程碑、任务、依赖、责任、阻塞与验收。PROJECT 和看板由同一数据生成，禁止另写任务状态。
- 开工必须有实际负责人；完成必须有验收范围、验收者和证据。受控测试不自动升级为真实运营，里程碑独立验收。
- 自动检查重复编号、引用、循环依赖、未满足依赖的开工、在制任务上限、缺失证据和陈旧视图，接入现有 npm 检查。
- 管理改进有问题、基线、选项、试验、效果、采用/撤回记录；真实自主改进协议明确不能向模型泄露预设管理答案。
- 原 U-001–015 和旧 PLAN/OPS/ENG 编号保留；本次维护来源明确为外部工程代理，不宣称公司自行实施。

## 范围

采用仓库内 JSON + Markdown + 无额外依赖的 Node 脚本，先满足当前小团队交接。所有规则是本项目可调整的工作约定，不是运行时授权机制或通用组织章程。本轮不增加模型调用、公司成员、采购、宿主权限或定时运行，不重建独立 HTML 管理站点。

## 验收

1. 人与工程 Agent 可由统一入口知道当前状态、阻塞和下一工作项。
2. 一次修改主账后可生成总览/看板；只改展示或错误声明完成时检查失败。
3. 记录本轮管理改进、下一工作批次、公司接管前提及未来工具选型标准。
4. 通过管理规则测试、既有 npm 检查和 Python 回归。真实公司自我改进仍保持未验收。
