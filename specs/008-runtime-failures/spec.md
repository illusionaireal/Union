# 008 · 实际运行失败的可诊断性

用户反馈首版不能正常运行。当前没有用户现场报错、供应商或运行记录，不能认定现场根因。同步最新 `dev` / `54e35b5` 后，本机干净启动通过。

已复现的确定缺陷：运行和观察层把 HTTP 参数错误、输出截断、决定校验失败统一隐藏成“核对宿主记录”，网页无法定位失败步骤。成功脚本验收遗漏此路径。

第二个已复现缺陷：连接测试强制 `min(512, configured_max)`，需要更多输出额度才能产生完整结果的模型会被判失败，且调高连接上限无法生效。修复为测试沿用用户配置的有限输出上限；确认页显示上限及超时。按仓库要求独立复核调用资源影响。

本轮要求：显示宿主生成的错误分类、HTTP 状态、白名单参数和恢复说明；在回执、运行记录和总览保持一致并持久化。供应商错误正文、私有日志及密钥仍不公开。未知执行和未知用量保留核对要求，不自动重试或切换协议。原调用占用、预算与权限规则不变。

验收：本地 HTTP 400、截断结果、无效启动决定的回归；浏览器失败后编辑配置、明确手动重测、刷新后错误可查且不泄漏回显凭据。真实供应商及用户现场复现仍为待办。
