# 016：成员隔离工作区

延续用户启动 ai-union-corp 的指令，补齐成员只能产出文本、不能实际开发的工程缺口。它是可选业务能力，不是所有组织的必需能力。

## 规格

- 复用现有 Deep Agents 循环，新增 `workspace_execute` 工具：成员可在指定工作区用命令读取、修改代码并测试，后续成员可读取同一工作区。
- 宿主绑定工作区及已安装的 Docker 镜像；章程允许、岗位允许、有效任职和在途工作同时满足才能执行。模型不能选择宿主目录、镜像或容器选项。
- Docker 容器只挂载业务工作区，隔离网络、只读根、非 root、限制内存/CPU/进程/超时/输出。无 Docker 时明确受阻，绝不降级为宿主 shell。
- 一轮模型调用至多一个工作区命令；持久记录实际命令、配置版本、执行状态和结果。未知结果阻止新命令，重启或检查点不能重放；原运行及工作区回执均须核对。
- 工具结果不代替正式交付。成员最终交付应说明真实修改、验证、限制及后续事项。
- 不自动开放联网、发布、仓库远端写权限或运行系统自身目录。部署仍须另行接入实际授权的运行资源。

## 验收

验证章程/岗位/任职/暂停/版本、路径重叠、同轮混合工具、幂等、超时及中断不重放、真实 SDK 工具往返和跨成员读取结果。容器引擎替身与模型替身明确标记，不能据此宣称真实容器隔离或组织自主开发已通过。资金/授权实现按 AGENTS.md 由另一工程角色审阅。
