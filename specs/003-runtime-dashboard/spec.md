# 003 组织运行 Dashboard

范围更新：用户进一步要求可操作的前端。本文现在定义[组织操作工作台](../004-organization-console/spec.md)中的观察模块；此前“整个网页首版只读”的限制已撤销。本文读取行为的只读保证仍成立，写操作按 004 独立授权与验收。

## 来源、地位与状态

来源：用户明确要求“dashboard 也是项目的必要组件。加入到开发需求中”。这是对原 F11 观察入口的新增要求，优先级为 **P0／必需组件**，纳入首版产品验收。

当前状态：**需求已纳入，尚未实现或验收**。现有 CLI 提供观察数据，开发进展网站及单 HTML 展示固定验证快照；它们不满足本需求。运行时机制已完成的结论保留，首版产品还须完成 Dashboard。

统一产品与流程依据见 [PRD](../../docs/PRD.md)，页面与交互见 [产品设计](../../docs/product-design.md)。高保真原型使用明确标识的设计模拟数据，不代表 Dashboard 已接入运行数据。

## 用户目标

用户打开 Dashboard 后能看懂：组织现在做什么、由谁负责、已经产出什么、下一步是什么、为何受阻、资源还剩多少。页面应读取指定组织的实际持久化记录，组织使用 fixture 时明确显示模拟来源。

## 必需能力

| 编号 | 需求 |
| --- | --- |
| D01 | 总览显示组织身份与目标、章程及状态版本、当前阶段、待办、下一步、复查时间和阻塞原因。组织状态、执行记录、宿主执行活性和观察服务连接分别显示：有有效宿主活性依据的在途执行显示正常执行；仅有遗留 running 记录而活性不足时显示“活性未确认”；已确认未知结果显示待核对。不得仅因 running 就报正常运行或需人工核对。 |
| D02 | 成员与岗位显示成员身份、当前任职、负责的任务及交接关系；不得把 fixture 成员标为真实 Agent。 |
| D03 | 工作列表可按状态、成员筛选，详情展示任务责任人、依赖、执行状态、完成或失败说明、关联决定及成果；区分等待依赖、等待事件、失败、暂停与待核对。 |
| D04 | 成果支持查看与下载，显示任务、成员、执行来源、版本和 SHA-256；读取实际文件并校验，文件缺失或校验失败时明确报错。 |
| D05 | 事件和决定以可追溯时间线展示，关联任务及执行 ID，保留接受／拒绝及其原因；支持分页或增量加载，不无限追加到页面。 |
| D06 | 执行与资源展示执行器、模拟／真实来源、状态、已有开始与结束时间、累计调用占用与上限、可用 token 回执和额度阻塞；未知费用或缺失回执显示“未知／未提供”，不得填成 0 或编造预算。 |
| D07 | 接入组织数据服务，支持手动刷新及自动刷新。页面可见且服务正常时，自动请求间隔不超过 5 秒，设置有限超时并防止请求积压；显示组织 ID、状态版本、采集时间和最后成功刷新时间。响应携带服务实例和请求／快照顺序，旧会话或旧响应不得覆盖新内容及连接状态；组织版本不变时，新增事件、拒绝决定、决定执行及用量变化也须更新。 |
| D08 | 首次加载、空组织、无任务、服务断开和恢复均有明确状态。失败时保留最后成功数据并标为过期；恢复后刷新。一次快照内的状态、决定、执行和计数须保持一致。 |
| D09 | 首版提供单 HTML 前端，内置样式与脚本，连接同源只读数据服务；兼容桌面和手机，支持键盘操作。脱离服务时只能显示明确标识的快照或断开状态，不显示实时连接成功。 |

## 首版范围与数据边界

- 单组织、本地运行，组织目录由启动配置指定。数据服务复用现有运行时语义，以白名单返回观察字段，不直接暴露完整数据库、工作包或私有日志。
- 页面读取、刷新、筛选和下载均为只读，不启动模型、不派发任务、不消费事件、不触发唤醒或恢复、不占用调用额度。
- 董事会凭据、认证资料和私有执行日志不得进入响应或 HTML。执行器错误仅展示适合观察的摘要。
- 工作台纳入网页创建、运行、暂停派发、事件、资源、修章和执行核对，按 004 的身份、权限、版本与回执规则实现。观察模块不得隐式执行这些操作。公开或多用户部署需相应访问控制，不能通过公开展示站点暴露组织数据或命令入口。
- Dashboard 的 fixture 验收与真实 Agent 能力验收分别记录；看板读取实际测试数据库不等于真实模型已经运行。

## 验收标准

| 编号 | 可复现的通过条件 |
| --- | --- |
| A01 | 打开指定组织，页面身份、目标、版本、任务计数、下一步及阻塞原因与该次数据库快照一致；另一组织的数据不混入。 |
| A02 | 用已有 fixture 驱动两名成员、依赖任务、三份成果和后续决定，页面能追溯它们的关联并保持模拟标记；筛选与详情可用。 |
| A03 | 服务正常且页面可见时，5 秒内发起下一次自动读取，数据在新响应成功后显示；手动刷新立即请求。验证同版本新增事件、启动决定执行造成调用占用变化仍显示；将新响应先返回、同版本旧响应后返回，页面内容、时间及连接状态不得回退。 |
| A04 | 分别演示等待依赖、等待事件、失败／暂停、未知执行待核对和额度耗尽，页面给出对应原因；不能仅以统一“运行中”表示。 |
| A05 | 成果下载与经校验文件内容一致；缺失或篡改文件明确失败，不报告交付文件可用。 |
| A06 | 断开服务时显示断开及最后成功时间，旧数据标为过期；恢复服务后更新。数据库持久状态不被当作活跃进程证明。 |
| A07 | 多次访问、刷新及下载前后，状态版本、事件消费标记、执行数和资源占用不变；接口响应不包含凭据、认证资料或私有日志。 |
| A08 | 同时提交变更与读取时，各次快照内部一致；原机制回归通过，桌面和手机的核心查看流程、键盘及空／错误状态通过浏览器检查。 |
| A09 | 用受控慢执行器让派发进程保持活跃并读取看板，工作／决定正常执行不误报待核对；再分别验证宿主活性无法确认和已确认未知结果的文案。观察不得调用 recover 或重派。 |
| A10 | 观察服务重启、组织身份变化及长请求超时后重新读取；旧会话响应不混入，断开／恢复与最后成功时间仅由当前有效响应更新。 |

实现步骤见 [plan.md](plan.md)，待办见 [tasks.md](tasks.md)。全部必需能力完成并有验收证据后，才能将 Dashboard 标为已交付。
