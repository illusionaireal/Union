# 可替换工具服务契约 v1（U-025）

2026-10-28。此规格是平台接入实现的输入，不是已部署目录、SaaS、计费或授权服务。AU可选择平台、第三方开源/托管服务或自建能力；组织选择与宿主实际授权分开。

## 对象与边界

| 对象 | 必需信息 | 谁负责 |
| --- | --- | --- |
| ToolDefinition | 稳定id、provider_ref、版本、能力说明、输入/输出约定、数据范围、部署/维护要求、价格说明版本 | 提供方维护；平台验证接入兼容性 |
| PricingDescription | kind=free/metered/subscription/external，版本、生效时间；涉及金额用整数最小单位和currency，未知明确标记 | 服务方提供，实际报价和账单另验 |
| ToolBinding | id、au_id、tool版本、实际grant_ref、有效配置的公开部分、状态、资源责任、数据导出能力 | 宿主在有效授权内绑定；AU可申请选择 |
| InvocationReceipt | id、binding_id、AU/岗位/任职/工作引用、请求标识、起止时间、结果状态、用量、费用已知/未知及结果引用 | 执行宿主持久记录 |
| DataExport | owner_au_id、格式/版本、范围、来源及导出引用、关联任务编号与证据 | 数据归属按约定；持有不等于可任意向外发送 |

能力描述不是实际权限。绑定配置里不放Key/令牌；秘密存宿主私有配置，资料来源和工具输出不能改变授权。标注免费不代表模型/服务器等全部成本为0。

## 最小宿主适配接口

这是协议命名，不是本轮新增HTTP端点：

- list_tools(query)：只读可用服务说明和价格信息；不自动订阅或调用供应商。
- request_binding(au_ref,tool_ref,purpose)：AU提出需求，可关联现有support_request；返回申请回执。
- activate_binding(trusted_context,request_ref,grant_ref)：宿主验证实际权限、当前版本和资源后启用；AU模型不能仅凭批准文字自行激活。
- invoke(binding_ref,acting_assignment,work_ref,request_id,input)：执行前重验有效绑定、任职、章程与资源，记录回执；读取和外部副作用的幂等策略由工具契约明确。
- suspend/revoke_binding(trusted_context,reason)：阻止新调用，未决调用保持可核对；停用不伪装取消外部已执行行为。
- export_data(trusted_context,scope)：返回受控导出引用，保留任务ID、证据关联和版本；对外传送另看实际授权。

## 状态与失败

申请状态可复用pending/needs_information/accepted_for_action/declined；它不等于绑定状态。绑定为inactive/active/suspended/revoked，只有宿主可改变有效状态。调用结果为accepted/running/completed/failed/unknown；unknown保留资源占用和原请求标识，查供应商回执后再决定，不盲目重复提交。

绑定切换或撤销后旧会话检查点不能继续取得权限。服务版本/价格变更需重新确认适用条件，不默许付费升级。服务失效应报告具体能力缺失，让AU选择等待、替换或申请资源。

## 首个免费工具验收（U-026）

从真实U-006/U-019需求选择，不为工具商城而创建需求。先评估现有仓库主账/观察服务是否能复用；服务化前验证实际身份和组织数据隔离。两个AU同名任务不混淆，导出/替换保留U编号与证据，撤销后不能继续调用。AU选择、使用、评价工具的真实记录与工程替身测试分开。

## 付费阶段（U-032）

基于真实需求和明确支出授权，关联价格版本、开通/取消、实际用量、账单核对及未知结果。采购或开通记录不能作为付款成功凭证，mock不等于真实结算。共享服务和父子AU必须说明谁承担一次调用/费用，不能重复扣记或凭空复制额度。真实支付另走独立设计与权限/金额复核，不在本契约中默认启用。

## 迁移与验收

适配器不要求改写现有第三方工具。迁移先确定唯一主账，准备导出映射和回滚，验证一次有界数据搬迁及读回后再切换；不能同时维护两份独立状态。第三方许可、托管成本与维护责任由实际选型核实。

v1契约完成指能力、费用、绑定、调用/撤销、导出及回执边界已经定义。实际目录、适配器、免费服务及商业验收仍由U-026/032分别完成。平台服务可选，不成为AU定义或成立门槛。
