# 009 · 普通对话与组织工具

用户明确纠正：不能把每次模型调用都做成整包 JSON Schema 考试。首先恢复 API 的普通调用能力，并使组织初始化表达清楚。

API 连接测试只检查普通文本回复；工作正文直接作为成果保存；只有组织变更使用工具参数。初始化以成员姓名、岗位职责、负责人和首批任务表达，宿主生成标识、任职记录与版本依据。后续决定使用受当前章程及岗位限制的组织工具，继续事务提交和权限校验。

API 请求不再发送 response_format，也不在消息内附整包 Schema。旧连接配置可读取，旧输出模式不再影响 API 行为。根地址和完整 chat/completions 地址均可用。网页不再要求用户选择结构化输出模式。模型必须支持 Chat Completions 的工具调用才能组织协作；普通连接测试不证明工具能力。

已收到完整响应但遗漏工具或提议校验失败时，在用户本次调用额度内允许一次带反馈的修正。每次 HTTP 请求独立占用一次调用并记录用量；未知执行、HTTP 故障、拒绝和截断不自动重发。工作正文不尝试猜测并执行其中的指令；遇到无法完成的任务可调用报告受阻工具。

本轮聚焦 API 执行器。现有 Codex CLI 结构化适配器保留并明确标为旧路径。真实供应商和模型能力须独立验收，本地 HTTP 替身不能证明它们。
