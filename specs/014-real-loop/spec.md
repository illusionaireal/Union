# 014 · 真实筹建与执行循环

用户目标：用真实 API 完成筹建，持续正确执行 LOOP；HYB 不可用时允许 OpenRouter 免费模型。开发主线 dev。

- 不预填团队、岗位、任务或模型成果；至少两名正式成员，使用正式 Console/API/Harness。
- 工具往返、实际筹建、业务质量分别验收。免费模型使用实时目录的显式 `:free` 型号，失败和未知保留。
- 组织轮次只展示组织工具；成员任务保留独立虚拟文件会话。通过 SDK 的工具排除能力收敛工作流，保留其安全中间件和既有 Engine 授权。
- 已提交成果正文内联传递，宿主存储路径不进入模型资料。草稿路径不是跨任务交付。
- 新排程可使用成员姓名/ID、已有任务标题/ID或成果ID。宿主解析唯一有效任职、生成工作ID并建立真实依赖；歧义、缺失引用和重复标题拒绝。旧 update_organization 保留。
- 简单等待入口接受原因和 1–86400 秒复查间隔，宿主生成 UTC 时间；无新事件时不调用模型，有限监听期间新事件可唤醒同一作业。
- 身份、版本、当前权限、原子提交、暂停、未知核对与资源上限继续由既有 Engine/Console 管理。新工具不接受 actor、岗位覆盖或版本号。
- 历史检查点保留。组织轮次的工作流变更使用新会话键；成员文件会话不因该组织工具变更重建。
- 真实验收如实区分：成立、首批交付、后续安排、后续交付、空闲唤醒。达到资源上限应停止，不能宣称仍常驻运行或完整自治通过。

首轮采用32次组织调用；发现真实失败后另采用最多8次修复验证，再单独采用最多8次空闲/唤醒验收，累计48。所有轮次保留，未重置计数。经营首版三章/三周期验收不由本次筹建试验替代。
