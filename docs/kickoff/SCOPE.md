# PLAN-001 · M0 范围工作稿

启动日期：2026-10-10（Asia/Shanghai）。依据 UNION-B1 与用户“开始启动项目”指令。
状态：准备中；沿用产品原则，具体供应商和外部可用性尚未冻结。

## 本轮边界

- 一个经营 Union，至少两个隔离测试租户。
- 工作假设：允许使用的公开资料生成数字研究简报；具体细分机会、产品、价格由经营 AI 提出。当前没有替 AI 人工选择客户或制作销售产品。
- 支付使用本地 Mock；渠道仅本地事件夹具；本轮没有外部模型、邮件发送、投放、真实收款或链上操作。
- 技术默认仍为 TypeScript/React + Temporal + PostgreSQL。当前 SQLite 仅验证动作协议，不能改写生产选型。
- 测试链、模型、正式渠道、真实支付服务商：PLAN-002 待验证。M0 草案不承诺账户已经可用。

## 用户路径与角色

投资人查看证据 → 测试认购 → 自动达标启动或退款 → 查看经营与测试分配。
客户查看产品 → 支付 → 自动交付 → 查询或退款。
AI 提交结构化动作；确定性网关校验权限与预算后执行。投资人没有经营审批权限。
平台建设者维护共用能力；为单 Union 人工定价、获客或交付必须记录为经营干预。

## 验收场景与证据

| 场景 | 期望 | 本轮证据 |
| --- | --- | --- |
| 模型要求未知工具、修改预算或跨租户动作 | 拒绝，预算不变 | 离线授权测试 |
| 多进程竞争同一预算 | 总预约不超过硬上限 | SQLite 并发测试；待 PostgreSQL 重跑 |
| 外部成功后 Worker 进程退出 | 按原幂等键查询恢复，不重复效果 | 独立 Mock 数据库和子进程崩溃测试 |
| 超时且无法确认效果 | 保留预约，等待核对 | 未知结果测试 |
| 重复请求改金额、目标、币种 | 拒绝幂等冲突 | 参数绑定测试 |
| 无效报价、交付失败、退款失败 | 按规则拒绝/暂停并显示义务 | 待 ENG-011–016 |
| 测试认购未达标 | 自动退款，保留外部凭证 | 待 ENG-018–022 |
| 无真实订单 | 技术测试可完成；商业验证不能计成功 | 后续 G1/G2 分开验收 |
