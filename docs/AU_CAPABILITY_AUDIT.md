# AU 观察与调整能力核查（U-018）

2026-10-28；基线 `dev@0d4e824`。本次完成接口审计与受控行为验证，不改变运行时代码、权限或公司状态。

后续实现更新：020已增加现有决策任职的有界诊断；021已记录宿主生命周期和指标；022已接兼容治理投影；023已提供显式授权的申请记录。以下矩阵保留本次基线审计含义，具体当前范围及验证见[批次收口](../evidence/026-batch-closeout/README.md)，不将历史缺口当作当前仍未实现，也不把工程实现当真实效果通过。

核心结论：**组织决策岗位已经可以依据全量本地工作、成果和待处理事件调整内部组织；普通工作成员没有同等观察/决策入口。当前无需重写组织循环，先补有限历史诊断与工作时间证据，再完成真实交付和自我改进验收。**

## 1. 怎么核查

1. 从 Engine 构建上下文，检查 agent_protocol.model_input 实际投影和 tools_for 提供的工具；读取方法存在不等于成员能调用。
2. 新临时组织执行创建、文本交付、受阻、交接、恢复、内部记忆/任务更新及未知执行阻断等真实引擎行为。
3. 现有真实 SDK + 回环 HTTP 测试复核资料与工具到达供应商请求体、权限撤回和未知恢复边界。

重现命令（仓库根目录）：

```sh
.venv/bin/python -m scripts.audit_au_capabilities --output .union/audit/new-capability-probes.json
```

脚本只生成新临时 fixture，不接受真实组织目录，不调用供应商、Docker 或企业系统；输出路径必须是新文件。20 项探测包括验证已知缺口，表示“核查结论可重现”，不是20项产品能力通过。现有能力改变后要更新审计，不把缺口断言永久加入 CI 来锁死未来实现。

证据：[20 项行为探测](../evidence/019-au-core-contract/capability-probes.json)、[SDK/协议复核](../evidence/019-au-core-contract/sdk-tests.log)。后者仅为实际 SDK 和本地 HTTP 替身，不证明真实模型行为。

## 3. 调整与行动矩阵

| 行动 | 现有真实接口 | 当前可执行者 / 约束 | 核查结论 |
| --- | --- | --- | --- |
| 筹建成员/岗位与首批任务 | 分批 bootstrap 工具，或 initialize_organization | 临时筹建身份；成立后失效，草案不等于正式成员 | 已有机制，010 受控与014局部真实证据；当前公司仍未筹建 |
| 正式运行后增加成员、岗位、任职 | update_organization → create_member/create_position/assign | 当前决策岗位、有效章程及权限交集 | 已有可用；不是 init 后冻结组织 |
| 更新岗位职责与工具权限 | update_position | 不超章程允许列表；授予工具名不等于宿主已绑定 | A03；宿主工具授权另验 |
| 同 AU 内任职交接、变更决策岗位 | handoff/set_policy | 有效决策提议；在途工作需核对，历史任职保留 | A03；不是跨 AU 转移 |
| 创建后续工作 | schedule_work；或 create_work 明确岗位 | 有唯一有效任职时可用姓名快捷方式；兼任时必须明确岗位 | A01/A04/A05；快捷工具目前会拒绝兼任歧义 |

| 普通成员建议改进或报告受阻 | 交付正文/report_blocked | 自己的正式工作；可由协调职责接续 | O04；普通成员不能直接调用组织决策工具 |
| 向治理方提出资源/工具需求 | 可以写工作/记忆、wait 原因 | 缺少有状态的申请、处理人与响应关联 | A02/A06；U-034 不应变成自动授权/采购 |
| 调整目标/章程/预算或核对未知执行 | board/受信 CLI/Console 的现有入口；不是成员组织工具 | 实际 board/session 权限，目标也没有现成任意修改命令 | A07/R01；不应为自我改进解开限制 |

| AU 委托、派生、拆分合并 | 当前无关系/资源交接协议 | Console 多组织创建不授予组织创建他者的权限 | A07/I01/I02；U-027–031后续 |

主要源码：[agent_protocol.py](../ai_union/agent_protocol.py) 的 tools_for/compile_tool；[engine.py](../ai_union/engine.py) 的 _authorize/_operate/finish_work；[workspace.py](../ai_union/workspace.py) 的 available/authorized。

当前调度还有限制：`runner.step` 优先派发就绪工作，通常在无就绪工作且有事件时进入决策；待处理事件不意味着立即打断当前队列。未知/在途执行在新决策之前阻断，需要受信核对。自主复盘的时机和长任务容量须在真实场景观察，不能仅因工具存在就宣称持续自我改进。

## 4. 单 AU 身份及治理限制

- 成员 ID 存在各自组织 state 中；两个 AU 内相同本地 ID 是不同作用域身份，不是已实现多 AU 同时任职。引用应补齐 AU 域；目前没有全局成员注册表或跨 AU 成员转移，I01/I02验证本地对象必须存在。
- 引擎允许一个成员在同 AU 多岗位；不应为了方便 schedule_work 而禁止兼任。工具快捷方式的歧义有明确岗位操作兜底。
- 当前组织内部决定统一由 policy.decision_position_id 的有效任职发出。可以调整该责任，但尚无任意多治理主体、多审批人或企业身份映射。
- board_name 是显示和回执身份，board_hash/salt 是实际本地控制验证。只改名称并不等于接入公司 SSO/审批系统；U-022选择兼容描述，不修改授权程序。
- 普通任务与协调职责的资料分层是已有机制，不是完整岗位知识访问策略。记忆全量、决策角色全量成果与长上下文容量都需如实说明。

## 6. 仍未验证什么

本审计没有证明模型能主动发现问题、作出正确管理决定或产生有效改善；没有企业系统、真实容器和持续主机证据。真实 U-019 按独立协议验收。当前 ai-union-corp 的模型与主机阻塞未因本轮探测解除，未知运行仍须由受信入口核对，不能通过让决策 Agent 重试绕过。
