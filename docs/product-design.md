# ai-union V1 产品体验与交互契约

版本：U-110 v1，2026-11-13。依据：[Main Chapter V1](UNION_CHARTER_v1.0.md)、[PRD](PRD.md)、[产品审计](reviews/2026-11-11-kanban-charter-product-audit.md)及用户要求的“先纠正 Kanban，再派单执行”。

本文拥有完整用户体验契约；[FRONTEND](FRONTEND.md)拥有路由、组件、接口消费和实施责任。当前代码核查基线为 `d27d543`。目标流程不表示能力已实现；工程、真实模型、用户和持续运行分别取证，运行态只查 Kanban。旧设计可在该提交追溯，不再约束重构产品。

## 1. 产品结果与取舍

用户应能建立有明确目的和责任边界的 AU，在合法资源范围内持续推进工作、交付可读成果、吸收反馈、处理异常并改进。用户不用成为内部命令操作员、资料路径搬运者或每轮执行的调度员。

保留 React/TypeScript/Vite、正常登录和已验证的核心能力，重建信息结构、默认入口与完整旅程。旧 AU 迁移、旧导航、旧控制台布局没有保留义务；历史数据、原请求、权限和未完成责任不得因换界面被删除。

| 方案 | 结论与依据 |
| --- | --- |
| 在旧治理控制台加按钮、换样式 | 不采用；仍缺完整旅程，重演 U-109 审计中的日常人工接力 |
| 缩成聊天页或一次报告生成器 | 不采用；不能表达连续责任、治理、等待、反馈、资源和组合义务 |
| 以组织空间和持续工作为主轴，接入既有正确内核 | 采用用户已授权的重构方向；一套交互契约，逐片接通，未支持范围明确呈现 |

单 Agent AU 是完整合法路径，不为界面造第二成员、行业角色或层级。多成员、组合和改进随实际需要与有效授权启用。平台账户、付款和宿主权限不替代核心身份或 AU 治理依据。

## 2. 信息架构与默认入口

登录由同源核心身份边界处理。无可访问 V1 AU 时进入组织列表与创建入口；合法深链接优先，其他情况只恢复同主体最近访问且仍有权限的 V1 AU，否则返回列表。不得默选列表第一项、其他主体的 AU 或 legacy 组织。

| 入口 | 路径契约 | 用户在这里完成什么 |
| --- | --- | --- |
| 我的组织 | `/organizations`；`/` 导向这里或合法最近空间 | 选择/创建 V1 AU，看目的与准备缺口；账户操作独立 |
| 组织概况 | `/au/:auId` | 看目标进展、当前责任工作、最近成果、需谁处理的事项与真实能力边界 |
| 工作 | `/au/:auId/work`、`/au/:auId/work/:workId` | 提出目标、观察连续进展、补充输入、追溯责任与原执行 |
| 成果 | `/au/:auId/results`、`/au/:auId/work/:workId/results/:resultId` | 阅读正文、版本/来源/采用依据，下载和针对版本反馈 |
| 关注事项 | `/au/:auId/attention` | 按影响范围处理授权、保留决定和恢复，看等待对象与唤醒条件 |
| 能力与资源 | `/au/:auId/resources` | 连续完成模型、工具、业务资料和预算准备，核对用量与未知费用 |
| 治理与成员 | `/au/:auId/governance` | 看当前有效规则/任职，作有权决定、撤权和交接 |
| 改进 | `/au/:auId/improvement` | 看问题、试用、效果比较和采用/撤回，复用原工作与成果 |
| 合作 | `/au/:auId/collaboration` | 适用时处理承诺、履行、争议与组织变更，不从视觉层级推导权限 |

概况聚合摘要，不另存权威事实。工作详情聚合输入、执行事实、成果和事项；成果可单独阅读，不必先进入治理页。导航围绕对象，不是内部操作步骤清单。

移动端直接保留概况、工作、成果、关注，其余在可键盘操作的展开导航；不靠横向溢出隐藏操作。内部 ID、协议和 JSON 放到按权限开放的诊断详情，不要求用户理解它们才能工作。

旧 `/overview`、`/tasks`、`/artifacts`、`/models`、`/members`、`/resources`、`/activity`、`/settings` 在 U-111/U-115 迁移期仅解析链接：合法 V1 作用域 replace 到新入口；无作用域回列表。旧 AU 链接解释支持范围，不挂载旧页面、不读取旧业务投影、不迁移或新建替代 AU。最终保留的是链接解析，不是第二套界面。

## 5. 状态、权限与恢复的共同合同

### 5.1 分开显示事实

| 维度 | 界面语义 | 禁止推断 |
| --- | --- | --- |
| 治理/准备 | 未绑定、准备中、受支持治理有效、具体缺口 | 本地治理有效不等于自主业务或预算已授权 |
| 工作 | 收存目标、待准入、可推进、推进中、等待、候选、已采用、已交付、结束/交接 | 模型自述、线程退出或HTTP200不能直接完成工作 |
| 执行 | 原Execution/attempt、当前所有权、最近进度/活性及时间 | 无输出不是死进程，断连不是远端停止 |
| 命令 | 待提交、受理/拒绝、处理中、待核对、已确认 | 200拒绝不是成功；404/回执单独403不证明未执行或整个AU失权 |
| 外部结果 | 已确认、未确认、部分完成、明确失败 | 本地取消不是远端取消、退款或副作用撤销 |
| 能力证据 | 实现范围、受控、指定真实profile、用户验收、持续窗口 | 单次测试/构建不证明全部模型或自主组织能力 |
| 资源 | 计划、授权、预约、消耗、结算、待核对 | 调用数不是金额封顶；未知费用不填0；重投/嵌套不增余额 |

这是视图词汇，不私增后端枚举。每个标签须有事实依据，或由负责实现卡增加可核对投影；不能将当前硬编码 `execution=not_started`、`autonomous_business=false` 简单反转。

### 5.2 身份与权限

界面作用域绑定当前 principal、service instance、AU；工作/成果再绑定 Work、Execution/step、result/version。读取、新动作、成果采用、本人原回执查询分别判定，服务端每次重验当前授权/版本。

切换主体/服务/AU时中止旧读取，清除旧受保护内容和下载，拒绝迟到响应；不删除服务端责任或回执。仅新动作资格不足仍保留合法读取和原请求核对。单独不能取得回执时重验身份/AU读取，不臆断整组织失权。

### 5.3 写入与恢复

- 一次用户意图提交前保留非秘密原引用及作用域；无法保存恢复引用则不提交。秘密、资料正文、目标全文和会话不进浏览器持久缓存。
- 当前身份/版本/连接修订/权限/能力变化时先刷新供核对，不静默换资源或扩权；正式采用与后续意图由领域/应用可靠关联。
- 确定拒绝保留输入/理由；传输不确定只查原 ID。重开、轮询、重连、重复点击或重挂载均不自动重放未知写入。
- 正常工作由服务端持久意图推进，不用浏览器连续 POST `start_work → start_attempt → run_loop → adopt → deliver` 替代组织责任；接续不能依赖页面存活。关闭页面、正常退出或浏览器会话到期不等于撤销已合法采用的运行授权；后续执行仍按当前治理、Mandate、资源与执行身份重验，真正撤权须阻止新动作和无效采用。
- 长工作保留新输入/观察，通用短读取超时不决定作业寿命；取消请求、送达、远端事实、未决占用分开显示。
- 等待/离线保留非秘密草稿和焦点，敏感输入仅在当前内存；恢复读取不自动授权新写入。后端已授权持久意图的恢复按原执行合同进行。

## 6. 资料、成果与费用

业务资料由有权接口提供名称、来源、范围、版本/摘要与使用许可。用户选择资料，不输入宿主绝对路径、目录别名或私有配置文件。缺发现/导入能力时 U-112 先补单一授权所有者和受控引用合同；不能用空下拉框或要求普通用户 SSH 配置代替完成。

S02 验证文本与正式业务资料分开标注；测试读取成功不表示 S03 已取得该文件/目录授权。行动与结果采用边界重验资料引用/版本/范围；组合和交接只传必要资料，不复制全部记忆。

成果身份是 AU/Work/result 的组合，result ID 仅在所属 Work 内唯一。详情路径保留 workId；缺失、歧义或越界明确拒绝，不能静默选另一成果。成果默认可阅读正文，保留原 Work、版本、来源、采用/交付依据和访问范围；下载是同一成果的另一呈现，不能只给摘要或JSON。候选和正式成果分开，反馈绑定版本，第二版可比较。外部/模型内容不在浏览器执行，阅读/下载均核验完整性及当前权限。

资源页分开显示授权、预约、实际尝试/用量和待核对。新金额带货币及整数最小单位，未知价格保留原用量依据；路由、监督、评审和改进均入账。调用额度不被表述为任意费用授权。

## 7. 治理与自治衔接

从“谁需要决定什么”进入治理，不把21种命令大表单作为首页。有效规则、保留事项、继任/退出与支持范围可读；不声称自然语言章程全部可执行。

外部资料和输入不因展示而取得指令权；正式行动只能经过可信命令路径。对外沟通显示所代表组织，不虚构人类。涉及个人资料或人工参与度量时说明目的、必要告知、最少采集和保留期限，不能默认转成对个人的持续监控；多租户身份、数据、凭据与资源隔离按实际边界验证。

授权内普通工作有机器推进路径。新能力/范围和保留事项形成持久关注事项，只阻塞相关工作。人的参与按补救介入、日常业务劳动、保留治理、自愿参与或不确定分类；测试中人手采用文字不算自治成果。

治理身份移交与工作责任交接是不同动作。U-114需处理 AI Work/Member/Mandate/Agent Definition 绑定、在途资格、原预约和必要资料，不能只更新旧 `state.work` 而遗漏 `state.work_runtime`。未知外部结果继续沿原引用核对；交接不自动扩权或清空责任。
