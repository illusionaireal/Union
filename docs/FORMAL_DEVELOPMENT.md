## 后续工作的完成定义

| 层次 | 必须提供的结果 | 不能代替它的证据 |
| --- | --- | --- |
| 工程实现 | 规格、代码、兼容性、行为测试、必要独立复核 | 只有计划、截图或静态表单 |
| 集成验收 | 真实目标依赖下的接口、认证、工具往返和故障回执 | 供应商替身或仅生成授权URL |
| 用户验收 | 固定地址登录→接入模型→创建/进入AU→真实行动→可读成果→反馈后后续行动 | 角色对话、模拟成果、只有连接测试 |
| 发布验收 | 指定候选构建、安装/升级/回滚、配置与数据迁移、恢复演练、已知限制 | 本地构建成功或没有实际采用的部署脚本 |
| 持续运行 | 约定观察窗口内的重复交付、空闲/唤醒、重启、故障、额度与维护责任 | 单次运行成功、测试数或代码量 |

每个工作项保留documentation/controlled/real/sustained范围。“工程完成”可以作为工程子项收口；对用户报告可交付版本时，必须另外说明未通过的集成、使用和发布门槛。不得把历史done条目或本阶段命名换算成产品整体完成率。

## 首个正式候选版的发布门槛

1. **正常使用**：首次受信设置后可用固定网址登录；模型保存/测试/采用、配置迁移、组织行动、成果和反馈路径连续可用；失败与恢复路径可理解。实际账号、模型权限和组织授权分别验证。
2. **真实接入**：候选版承诺支持的协议、供应商/订阅方式逐一有真实验收；未验的方式不得标为已支持完成。031模型接入对标仍逐行验收，不以目录条目数量替代。
3. **安装和升级**：构建可追溯到提交，依赖版本明确；配置、凭据与业务数据分离；安装、升级、失败回滚和旧数据兼容有可重现结果。
4. **运行和恢复**：在选定持久环境验证启动、停止、重启、空闲唤醒、未知执行核对、备份恢复和资源到限行为；未知结果不盲目重试，额度不自动增加。
5. **授权和数据**：宿主、平台管理员、AU治理方及成员边界明确；权限/费用变更有独立工程复核；凭据、客户资料和私有日志不进入版本库。版本化运行章程不能替代宿主授权。
6. **可维护交付**：有版本说明、限制、诊断入口与维护责任；项目检查、前端检查、Python回归及真实用户流程分别记录。观察窗口、样本和资源上限依据实际条件约定，不预设已经通过。

上述门槛不是新增花费、公开发布、生产部署、法律实体、开源许可或可见性变更授权。
