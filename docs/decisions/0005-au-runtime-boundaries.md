# ADR-0005：增量重组独立核心，并以公开契约接入平台

2026-11-08 S03 编码前增补：PR #17 的工具正文接续沿现有事实/权限分离，采用[限定契约](../../specs/053-union-rewrite/s03-tool-context-contract.md)。应用在同一 AU 事务中保存带摘要的私有 assistant/tool 轮次，领域仅保存引用；后续派发按当前权限重验，成果沿用实际输入的来源。旧历史不读时升级、不重读文件伪造回执；派发前预约和 PR #20 撤权事实仍分别待修复/复核。独立权限复核后才采用，不升级真实业务证据。

日期：2026-11-04；2026-11-05按Main Chapter V1修订。状态：**Accepted。S01/S05 与 S02 的限定所有者已实施并有工程证据；独立核心完整发布和真实业务能力未因此完成。**

## 依据、问题与选择

[Chapter V1](../UNION_CHARTER_v1.0.md) P-07、A-01–A-04、R-01、S-03和[采用记录](../CHARTER_ADOPTION.md)要求独立可用核心、领域独立、唯一事实所有者、公开平台契约及可靠迁移。[PRD](../PRD.md)定义用户结果。

原提案只写模块化，遗漏核心独立性和公开边界；本次修订同步[总体架构](../ARCHITECTURE.md)，不沿用旧稿的产品命名或两成员资格。

| 方案 | 取舍 |
| --- | --- |
| 在Engine/Console原位置继续追加所有规则 | 短期改动少，但领域、身份、事务、模型和平台继续耦合，无法落实A-02/A-04 |
| 新仓库、新栈和全面服务拆分 | 立即增加迁移、跨服务一致性和部署成本；五层参考图不要求五个服务，没有证据证明必要 |
| 当前工程内按用户用例迁移，逐步形成独立核心与公开契约 | 保留有效资产并逐片验证所有者/兼容；需要认真退出重复实现，不能只套转发层 |

选择第三项。语言和物理部署可后续依证据调整；本决定不指定永远使用SQLite或某一Harness。

## 已采用决定

1. 核心包含基础认证、AU权限和审计；无私有平台账户、仓库凭据或许可证服务也可构建/运行/验证。私有平台grant不能成为所有模型/工具的必经前置；选用现有modeld仍校验其AU grant/revision和凭据归属，独立性不授权绕过这些边界。
2. 领域规则不依赖具体Runtime、Harness、HTTP或存储。应用层负责命令、事件/执行意图和恢复编排；适配器负责实际存储、模型、工具/环境；按实际用例建立端口，不生成空壳。
3. 一个事实一个逻辑写入所有者。S01先固定创建/重开，后续逐用例重绑HTTP/CLI/React/平台调用者；未迁移用例仍由原实现负责。S11收口平台/外部管理的版本化公开契约，不能旁路内部表或模块。
4. 保留现有React、组织Harness与048单次模型服务分工。Agent定义/绑定明确关联责任、Work、Mandate与定义版本；模型服务不重复执行业务工具。轻量与确定性路径遵守同一语义，不强制完整模型循环。
5. 状态/意图原子或等价可靠关联；跨库/文件通过原请求、持久分配/意图、去重和核对恢复，不伪造跨系统事务。未知外部动作不因代码切换重派。
6. 公共协议、持久Schema、Agent配置、AU/任职/章程及连接版本分开。具体首片契约和旧调用者见[S01](../../specs/053-union-rewrite/s01-contract.md)，后续扩大前先固定受影响契约。
7. 迁移保留身份、历史、成果、预约和未完责任；读取不隐式迁移。新旧机制不得同时派发同一工作，保留的兼容适配必须有明确原因及退役条件。

## 采用边界、验证与回退

这是项目既定要求内的工程选择，记录者为外部工程代理；独立架构/需求复核见[S00证据](../../evidence/054-charter-v1-rebuild/README.md)。PRD与架构同步该方向。运行时仍为原实现；后续代码需严格TDD，权限/费用另行独立复核。

收益是可按用户结果迁移且责任可查；成本是阶段兼容与调用者核对。未迁移事实不由新模块复制。迁移不兼容或影响未知执行时停止切换，保留旧状态与证据，按已选契约恢复；不能用新fallback隐藏失败。

本ADR不选择开源许可证、不拆仓库、不执行发布/部署或业务数据迁移。P-07/A-04最终出口在S08/S11及其真实证据，不由本文件Accepted状态证明。

## S01 编码前细化（2026-11-05）

用户已授权完整 U-066。沿已冻结 S01 契约落实以下设计；本段在行为实现之前记录，实际通过范围由该片证据说明。

- auth/catalog 的当前版本分别为 1，以 catalog 的独立 schema 记录为准；旧未标记库是已知版本 0。新空库初始化版本 1，旧库在任何 Gateways、恢复、会话或 AU 写入前拒绝服务启动，显式升级才扩列和签发不可复用的 principal。选择独立 `identity_schema.py` 所有者，避免把迁移混入身份读取或继续堆入 Console。
- 升级使用既有 console 文件锁、SQLite 一致备份和单 catalog 事务。旧意图原文及 AU 文件不改；仅旧登录会话失效，旧账户绑定新随机 principal。回退检查升级后完整 catalog 的逻辑摘要及受影响表的单调写入标记；有新写入或备份损坏即拒绝。此标记是备份失效依据，不是另一套 AU 治理版本，也不对恶意宿主提供防篡改保证。
- 候选清单显式声明所需 auth/catalog 版本，缺声明的旧包只支持版本 0。当前发布器在切换和运行前检查实际库与目标候选；不兼容时不改代码指针，也不自动降级数据。直接绕开受支持发布器执行任意旧二进制不属于可保证的宿主权限边界。
- 共享创建应用流程保持一个请求命名空间和一个分配/登记所有者，profile 只决定实际存储适配器。窄 V1 库保存 state、charter 和创建审计，治理根在 state 中有唯一权威；不生成 board.key，不经旧 Engine 初始化，不把资源计划写成授予或预约。
- 纯创建规则从 Engine/Console 迁出，原公开校验入口保留兼容委托；新类型化 HTTP 错误不依赖旧字符串映射。legacy 创建、company 及原资源差异有实际旧调用者和回归，因此保留，退役须在后续调用者迁移后另验。

基线同步：总体架构的身份、应用、领域和 adapter 责任保持有效，具体实施顺序补在 [053 plan §8](../../specs/053-union-rewrite/plan.md)。本细化不改变 S01 DTO、T01–T12 或准备态的能力边界；权限/迁移/发布独立复核后才形成采用证据。

## S02 编码前细化（2026-11-06）

用户授权完整 U-072。沿既定增量所有者方向，按 [S02 契约](../../specs/053-union-rewrite/s02-contract.md)实现核心连接/有限验证，不开放 legacy Engine 写 V1，也不新建通用 Agent 循环。现有 `test_tool_connection` 两阶段消息/结果规则提取复用；S02 应用持久化阶段、身份与预约，modeld 继续只做单次原生推理。固定验证 Agent Definition 与连接 revision 独立，human Member 可以承担有界验证责任，S03 继续拥有任意目标工作。

比较：直接包装旧 Engine 会借用错误的 board/预算/责任；另建完整 Harness 会复制工具循环；选择迁出有界协议、增加 V1 领域/应用并复用单次传输。模型配置/资源/Execution 仍由 GovernanceStore 的 AU 事务写 state/审计；私有模型请求、资料和工具回执由窄适配器持有。显式首个模型命令把 schema 2 升 3，原创建、责任和治理审计保留，安装器拒绝不兼容旧候选。新增持久事实和版本不能靠忽略字段兼容。

独立核心用户只能提交自己的 API Key 或采用本 AU 的精确预授 grant，不因去掉 platform_admin 就取得宿主全部账号。新 API 凭据及其 grant 在 modeld 同库原子建立，AU 先记意图再发送；unknown 只查原 registration/grant。Go 凭据继续由已有上游 Credential 单一刷新，不能从其他认证库复制。

原请求事实收集与行动授权分开：modeld 保留撤权/取消后的迟到用量和结果，核心按原 attempt 记账，并在每个后续行动及接受点拒绝失效授权。否则“撤权安全”会造成已发生费用不可核对。该决定不弱化 grant 的新派发限制，也不表示远端已取消。

本节是编码前实施决定；独立复核、TDD、实际 profile 与安装证据完成后再同步已实现基线。旧兼容路径有真实调用者，保留原测试；S02 不双派发、不批量迁移、不部署。具体代码所有者/步骤在 053 plan §10。

## S02 所选 Codex 连接细化（2026-11-06，编码前）

用户为 S02 真实验收选择当前 Codex；本机选中配置是 API Key、Responses、`gpt-6-astra` 与 `reasoning_effort=max`。选择将该精确资源经既有 modeld 私有 API 登记并授予验收 AU，核心使用已有 `modeld_grant`。直接调用旧 CodexExecutor 会绕过 S02 单次推理/工具与用量边界；把 Responses 当 Chat Completions 会错误解释协议；扩展所有核心表单与凭据来源则超过此次必要范围。因此只给 modeld API 账号增加显式协议和设置，复用固定 SDK 的 Responses 单次流，不复制 Agent loop。

持久化仍由 Journal 唯一写入：原 registration 摘要含所有显式设置，旧摘要与回执保持；首次成功的显式协议注册在同一事务增加 nullable options 列并把私有库 user_version 从 0 升 1。读取/启动/失败不升级；受支持发布器在选择及运行前检查 manifest 的 modeld_schemas，缺声明的旧代码只支持 0，新代码支持 0/1，避免旧代码把 Responses 账号误当 Chat。直接执行任意旧二进制不作兼容保证。不增加双写存储、自动转换或自动协议回退；本次不迁移真实业务数据库。

契约及安装/回退、凭据、原生上下文和逐次计量验收固定于 [S02 Codex 细化](../../specs/053-union-rewrite/s02-contract.md)。实现后同步架构基线与模块说明；独立身份/持久化/费用复核及实际验收仍是采用证据，编码前决定本身不完成 U-072。
