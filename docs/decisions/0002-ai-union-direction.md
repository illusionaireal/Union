# ADR-0002：拆分 ai-union 与 UNION 平台，并调整开发主线

日期：2026-10-11。

状态：用户已确认产品方向与开发方法；本 PR 将决定纳入仓库。具体工程选型仍待首轮实现确定。

## 问题

原仓库以平台、支付与 M0 准备为入口。随后讨论明确了当前核心是围绕目标自行形成并运行的 AI 组织。若保留原 README 和全局 M0 开发限制，新 session 会继续优先做支付、PostgreSQL/Temporal 等平台工作，无法验证目标驱动的自组织体验。

## 决定

1. ai-union 与 UNION 平台分别规划，先在同一仓库记录边界。ai-union 优先验证组织 loop，成员执行复用已有 Agent。
2. 首阶段以商业组织开展，目标为“一个持续经营线上内容品牌的 AI 内容工作室”；岗位、成员、策略和流程由运行组织形成。
3. 董事会保留最终控制权，治理边界属于可修订的运行章程；岗位驱动权限和上下文，正式知识与成果支持跨成员交接。human-free 作为描述性指标。
4. 开发采用轻量 SPEC + 关键机制 TDD + Agent 评测，首轮为 `001-org-bootstrap`“组织启动与首次协作”。运行章程与开发规范分别管理。
5. 首版验证真实交付、外部反馈与下一轮行动。长期关注盈利或自维持，并区分融资与经营收入；首版不设盈利或零人工门槛。

详见 [DESIGN.md](../ai-union/DESIGN.md) 与 [DEVELOPMENT.md](../ai-union/DEVELOPMENT.md)。

## 对既有材料的影响

- README、AGENTS.md 和新状态页指向 ai-union 当前主线。
- 原 M0 状态与范围增加历史定位；原平台计划、任务编号、原文快照和测试证据保留。
- PLAN-001–006 的原 M0 门槛继续适用于原平台范围及其生产采用，不再作为新组织原型开发的统一前置条件。本决定不表示原任务已验收。
- ADR-0001 继续记录离线动作实验的技术选择与限制，其作为全项目下一步主线的优先级由本决定更新。
- 本次只改文档与开发指引，不改变资金或权限实现，不启用真实运行、发布或部署。实际服务授权和既有工程复核要求继续适用。

## 后果与验证

后续任务从首版组织体验推导，具体技术选择可依据仓库和试跑结果调整，并记录原因。下一 session 无需依赖旧对话理解项目。

提交前运行仓库规定的 `npm run check`，检查文档链接和基线完整性。这些检查不证明组织能力；真实 Agent 与外部交付验收在后续迭代按各自证据完成。
