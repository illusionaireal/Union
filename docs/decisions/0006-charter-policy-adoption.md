# ADR-0006：治理根先绑定，按支持范围采用 AU Charter

日期：2026-11-04；2026-11-05按Main Chapter V1修订。状态：**Accepted。S01 基础与 S05 `local_governance.v1` 已按精确契约实现；完整验证范围见各批证据。通用规则语言、多人程序及真实业务治理未验收。**

## 依据与问题

[Chapter V1](../UNION_CHARTER_v1.0.md) X-02(a)、D-04、C-02/C-03、P-04及[PRD](../PRD.md) F01/F03/F07/F09要求：有可识别初始治理主体和章程版本，授权变化实际生效，程序不能只依赖提示词。持有资源、对外承诺或长期运行还需最终决定方、保留事项、失能后的继任/恢复/退出。

原提案以legacy_board及五字段为起点，只讨论后续通用规则，容易把初始治理根也推迟。本次明确：复杂规则可以分期，适用治理义务必须在能力启用前满足。项目Charter、AU Charter、AGENTS分属不同权威边界。

## 备选与取舍

| 方案 | 问题或收益 |
| --- | --- |
| 全部由自然语言/模型解释授权 | 灵活但无法可靠约束真实身份、撤权、资源或采用程序 |
| 永久固定董事会和五字段 | 易沿用旧代码，但把当前局限当产品定义，不能满足V1治理根/失能程序 |
| 明确治理身份与采用依据，版本化受支持条款，按能力分期 | 可测试并如实说明缺口；需要契约、版本与兼容迁移，不能冒称任意文本可执行 |

选择第三项。

## 已采用决定

1. 初始治理主体是受信绑定的持续主体，默认创建者；不是用户填的board_name/controller_ref、平台账户可见性或模型自述。未绑定不得启用自主业务行动。S01明确新建与旧记录的来源/支持范围，S03之前满足受影响启用条件。
2. AU Charter共同引用有效版本、正文、受支持规则、采用依据和生效条件。持有资源/承诺/长期运行的AU需明确最终决定方、保留事项和治理失能处理；未知程序不能靠默认host全权或账号重置补出。
3. 当前身份、任职/授权、动作、对象、版本、宿主能力和资源在受控边界求值；正文不隐式给权限。未知、冲突或不支持的规则有明确结果，不能显示全部生效。
4. 修订按旧有效程序验证参与者、保留事项与采用条件，再可靠关联新版本及依据。新条款不能授权自身采用；派发、工具行动和结果接受均在适用点重验有效授权，传播再委托；未知已发生动作单独核对。
5. `legacy_board`是兼容profile而非所有AU的永久治理形式。旧五字段按原实际行为读取；不补造旧创建者/继任规则，不在读取时转换或扩大权限。新治理绑定、迁移和旧调用者绕过防护由切片契约及独立权限评审约束。
6. 通用条款语言、多人治理、治理失能流程和新控制适配器逐项通过S05设计/实现；S10启用组合时验证授予限制、撤权传播/离线边界。未具备的能力拒绝启用并显示具体缺口，不能以它们尚未实现为由丢掉需求。

## 兼容事实与反例

| 旧字段 | 当前真实行为 | 不得推断的能力 |
| --- | --- | --- |
| text | 校验非空有界、版本保存、进入上下文 | 自然语言执行或正文—字段冲突自动求值 |
| allowed_operations | 与有效决策任职权限取交集，按操作校验 | 拥有所有宿主工具 |
| allowed_tools | 岗位、派发、接受和工作区执行点校验 | 工具名字自动形成实际绑定 |
| reserved_matters | 枚举校验、保存、上下文；关键入口仍固定board校验 | 删去事项自动下放权限或支持任意治理程序 |
| board_can_amend | 使用旧章程布尔值和实际board凭据校验 | 新文本自授权；false后已有合法自助恢复流程 |

有效旧程序修订应成功；仅新文本声称权限必须失败。有效新根绑定后可按已实现profile准备AU；无法识别原主体时不能伪造绑定。合法交接保留责任/知识；旧任职或跨AU同名提交不能取得新权力。规则不支持可形成待采用材料，不得记为已经生效。

## 状态与基线同步

### 2026-11-05 S05 编码前细化

用户已授权完整 U-069。按既定“明确治理身份、受支持程序、能力分期”方向，冻结 [S05 契约](../../specs/053-union-rewrite/s05-contract.md)：`local_governance.v1` 采用单一当前治理者/最终决定方、明确保留事项、预先确认的超时后继或超时退出。注册核心参与者只有认证身份；提名/独立确认才授予当前治理权。初始根不随交接重写。无需再次选择 Charter 或授权实现本片工程；真实 AU 选择具体主体/资源仍由其有效程序作出。

取舍：只保存政策 DTO 或只补 legacy 不能证明新 AU 撤权有效；提前建设通用规则语言、投票/调度/模型运行会越过本片。选择真实而有界的内部记录责任用例，贯通 Member/责任绑定、Work、有限 Mandate 再委托、本地提交与接受，用同一当前授权规则拒绝旧版本；它不是 AI Execution 或业务自治。暂存迟到事实不等于采用，失败/交接保留原责任。

存储决定：auth schema 2 显式区分 owner/core，沿既有显式升级和发布器；AU schema 1 准备态通过明确采用命令升级至 2。原创建快照及采用保持不可变，当前治理、版本审计和命令回执同 AU 事务。Catalog 是定位及认证来源，不再以原 creator 代替当前 AU 授权。当前授权与历史回执分开；legacy 继续拒绝已采用治理的 V1。身份/源事实/安装兼容具有持久影响，须独立复核及成对测试后才可记为已实现。

[总体架构](../ARCHITECTURE.md)、[首片契约](../../specs/053-union-rewrite/s01-contract.md)和[切片](../../specs/053-union-rewrite/tasks.md)同步本决定。S01 已实现服务器绑定的稳定 principal、不可变初始治理根、版本化准备态读取和旧入口隔离，见 [056](../../evidence/056-s01-core-creation/README.md)及[独立复核](../reviews/2026-11-05-s01-core-creation.md)。S05 的范围与证据见 [057](../../evidence/057-s05-governance/README.md)，不关闭完整 F09 或 S10；保存章程、激活受控本地治理和真实业务治理分别取证。

### 2026-11-05 S05 实施决定与基线同步

沿编码前决定实现独立核心参与者、当前治理投影、21 种治理/责任命令及原请求恢复。初始 creator 作为当前权限判断的旧分支已由 AU 有效规则替代，原创建回执的 creator 归属继续保留。治理领域与责任领域分工，应用编排一个 AU 事务，持久化适配器保存原始来源、所有 Charter、完整命令摘要和连续审计。初次合法规则拒绝保留 schema 1 的命令回执，防止同 ID 改内容；没有自动迁移或第二写入者。

身份、权限和安装兼容难以无成本逆转，且“初始根不等于当前治理者”“本地人类提交不等于 AI Execution”需要保留取舍，因此修订本 ADR，不另建重复决定。逐账号失败窗口保护多账号情况下的登录限流；仅 owner 重置不抹去其他参与者。基线同步落到 ARCHITECTURE、S05 契约、PRD 当前处置、React/开发和安装说明。独立工程审阅、严格 TDD 与浏览器/安装证据各自决定其可证明范围，ADR 不授予真实迁移、资源、模型或部署权限。

该选择有长期身份/迁移和权限影响，因此保留ADR及成对测试义务；实施采用需独立权限复核。模型、资金、宿主、部署或运行AU的修改均不由文档采用自动授权。

### 2026-11-06 S02 资源与只读能力细化（编码前）

S05 active 只证明本地治理有效。S02 另需显式有限 model resource grant、费用未知接受、V1 Charter 的 `read_document`、验证 Work/Mandate/成员/定义绑定；原创建资源计划不变成余额。单次验证原子预留两次调用，已发出或 unknown 仍占用，未派发的剩余次数可释放。新授权、修章或任职交接不能追认旧执行；原 attempt 的事实核对与当前使用资格分开。

V1 只读工具声明由旧有效修章程序采用；legacy Charter 不因新枚举得到权限。S02 的普通推理不要求组织 Schema，只有配置/授权/接受走可校验接口；资源用途固定为本次接入验证。此细化沿已经采用的条件启用方向，不重新要求用户选择 Charter，不授权任意真实账号/花费。精确契约见 [S02](../../specs/053-union-rewrite/s02-contract.md)。

独立兼容审阅发现，仅增加工具枚举却保留 schema 1/2 会使旧候选误判可用。选择在成功采用 `read_document` 章程时同事务升级为 schema 3（与显式模型配置共用初值），而不是增加安装器的字段特判或强制用户先保存连接。schema 1 原创建保持原枚举，拒绝/故障不升级，撤回工具也不降 schema；原创建和审计不改写。此段在修复前细化已有 schema 决定，实际兼容采用以 S02 安装证据为准。

2026-11-06 工程核对：上述 schema 3、责任/资源及受支持发布兼容边界已有 [058 独立复核与安装证据](../../evidence/058-s02-model-tools/README.md)。所选 Codex 真实认证失败时，原 Work/attempt、已占用次数及未知费用在重启后保持；没有补造成功成果或扩大授权。通用业务、其他治理 profile 和未来切片仍按原启用条件另验。
