# ADR-0003 · 正式工作台采用 React + TypeScript + Vite

日期：2026-10-14。状态：React/TypeScript/Vite技术选择持续有效；2026-11-13按用户重构要求补充界面责任。

## 2026-11-13：保留技术栈，替换MVP体验

用户已授权按Chapter V1重构并修正U-109审计问题。选择以[完整组织体验](../product-design.md)为产品合同、[FRONTEND](../FRONTEND.md)为路由/接口/文件责任；旧七页、profile分流、通用手工命令台不再是保留条件。技术选择不要求保留旧布局，也不引入新的独立HTML产品。

取舍：沿旧壳修饰会保留人工接力；另造聊天/报告MVP遗漏连续责任。采用同一React工程重建组织空间和对象页面，复用正确核心契约。默认入口/作用域由app路由与workspace单一拥有，业务页面不写领域状态；新完整工作由原应用owner持久推进。对应设计已记录，行为实现按U-111–115逐片验收，不据ADR声称已部署。

下文保留原技术选择背景；其中旧界面形态不覆盖本次产品合同。

原 `web/console/app.js` 集中了七页、轮询、表单、命令与详情，生成单 HTML。用户要求完整前端工程，同时继续复用 Python 运行时、SQLite、本机会话和命令接口。

选择 React、严格 TypeScript 与 Vite；React Router 管页面及 URL 状态，TanStack Query 管读取与缓存。页面、API、公共组件、操作与详情分别维护。命令不重试，不排队到恢复联网后执行；结果不确定时查询原回执。

构建产物由 Python 同源提供，`npm start` 构建后启动后端。开发模式采用 Vite 持续构建并手动重新加载，避免引入第二个来源和代理身份变更。代价是没有开发 HMR；后续若引入同源开发中间件，需要独立验证当前来源、Cookie 和 CSP 规则。

原独立单HTML演示/报告已在后续工程中退役，历史通过Git和证据保留；正式产品使用React工程与生产构建，不重新建立其源码或专用脚本。验证覆盖类型、关键交互、实际 HTTP/Chromium、静态边界和启动入口；这些验证不等于真实组织或外部部署验收。
