## 1. 产品定位与问题

用户给出目标，ai-union 围绕目标形成组织、开展行动，并根据结果持续调整。成员执行复用现有 Agent；产品承担组织的持续状态、授权、决定、协作、成果、记忆及反馈循环。

用户前端是**组织操作工作台**，覆盖建立、运行、管理、观察和异常处理。Dashboard 是其中的观察模块。业务软件优先复用 ERP、CRM、文件与工单等已有系统，通过受控动作接口连接；复用边界与架构见 [软件复用与 AI 适配](software-reuse.md)。

本产品解决三个问题：模型会话结束后责任与资料难以延续；多成员行动难以追溯到有效决定和实际成果；发起人难以判断组织在做什么、做成了什么、下一步是什么和为何受阻。

首个实例从“一个持续经营线上内容品牌的 AI 内容工作室”收敛为当前的**三周期小说公司试验**。 受众、策略、岗位和流程由组织在授权内形成，不在程序中预写行业工作流。两个及以上可区分成员是组织协作验证的最低条件。

## 5. 核心使用流程

### J01 建立与启动

发起人在网页填写组织名称与一句目标，采用受支持章程并设置有限资源；预览采用内容后创建，保存依据并显示“待形成组织”。创建不自动运行。随后选择执行器、本次有限步数与必要的等待窗口，查看费用状态后提交启动。启动 Agent 在临时权限内提出成员、岗位、任职和工作安排；校验通过后提交，临时授权结束。失败保留原因，不能把无效安排显示成正式组织。

网页提供实际采用、运行、资源和章程入口。提交后显示请求回执；只有服务端确认后才将操作标为成功。原型按钮只模拟这些流程，不产生真实模型调用或数据库写入。

### J02 观察协作与读取成果

观察者进入总览，先确认组织、数据来源、连接与更新时间，再查看当前行动与下一步。点击任务进入详情，沿依赖打开前置任务或成果；在成果中查看内容、版本、执行来源与校验状态，并下载。成员执行完成后，事件进入决定循环，后续工作及依据可以继续追溯。

### J03 理解受阻与处理

工作台区分等待依赖、等待事件、正常执行、失败、暂停、未知结果待核对和额度耗尽。正常在途执行不得仅因持久记录为 `running` 被标为需人工核对。活性不足时显示“活性未确认”。发起人进入相关操作，查看目标、依据及影响再提交资源调整或核对；读取本身不触发操作。未知结果不会因点击“继续”而直接重派。

### J03b 暂停、调整与继续

请求暂停后先停止新派发，有在途执行时显示“等待在途回执”；回执确认后再显示已暂停。此时可在组织设置中调整资源或修章，预览新旧内容、受影响工作及提交版本。冲突时保留输入并要求依据新状态重新预览；继续运行重新校验资源与权限。暂停不代表已成功取消远程执行。

### J04 断开与恢复

首次读取失败显示无法连接及重试入口；已有数据时保留最后成功快照并标为过期。断开时不根据旧状态提交写命令，进行中的请求先查询原回执。恢复后读取完整快照，不把组织状态版本没增加当作数据没变化。刷新不会启动执行器或消费事件。

### J05 真实交付与反馈

M2 通过后，在获得实际渠道、账号和有限经营资源条件的范围内接入真实发布。组织依据可核验反馈作出下一轮决定并执行；没有反馈时明确记为没有反馈。这是 M3 工作，不是当前原型里的按钮或模拟场景。

## 8. 数据、状态与非功能要求

- 组织范围由服务端绑定；一次读取用一致只读快照返回允许的字段。读取、筛选和下载不改变组织、事件、执行或额度。写命令采用受信会话、服务端权限、基准版本与幂等请求 ID，先受理再以实际回执更新结果；不暴露董事会凭据、认证或私有日志。
- 组织阶段、执行记录、执行进程活性和观察服务连接状态分别表达。`running` 是持久记录，不能单独证明正常执行，也不能单独证明应核对；需要宿主活性依据或明确“未确认”。
- 自动刷新间隔不超过 5 秒（当前实现为 4 秒），手动刷新立即请求；前端取消或串行处理刷新，设置有限请求超时。旧会话或旧请求响应不得覆盖当前数据。组织状态版本供追溯，不作为跳过事件、决定与用量更新的唯一依据。
- 返回组织 ID、服务实例标识、请求顺序或快照序号、采集时间与组织版本。服务重启或组织变化时重新建立读取序列；同组织同版本的事件和执行变化也必须显示。
- 成果文件须校验；文本按文本呈现，不执行成员内容。缺失、篡改、未提供 token 和未知费用分别显示，不能默认填 0。
- 单组织、本地应用、SQLite、本地文本资产与一个真实执行器是当前工程选择。正式前端是 React + TypeScript + Vite SPA，按页面、功能、组件、API 拆分；类型检查、构建和关键交互测试是交付要求。Python 同源提供静态构建，安装后 `npm start` 一条命令启动。不再维护独立单 HTML 演示/报告，历史快照和验收记录保留。
- 页面可见且连接正常时持续更新；后台页面恢复可见后立即刷新。采用响应式布局，目标验证宽度 1440／1024／390／320 像素，核心流程可用键盘完成。
