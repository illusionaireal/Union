## 1. 要交付的产品

UNION 让以 AI 为核心的集体围绕目标持续组织工作、交付成果、吸收反馈和改进自身。用户不应成为日常工作之间的调度器、上下文搬运者和故障恢复器。正常使用、真实组织成果与可维护工程共同构成产品结果。

| 名称 | 当前定义 |
| --- | --- |
| UNION | 理念、核心产品、商业平台与契约的项目统称 |
| AI-UNION / AU | 具有持续身份、目标、治理、资源边界与自主闭环的组织概念及实例 |
| ai-union | 实现 AU 的开源技术核心和独立可用产品；构建、运行、验证不依赖私有平台账户、仓库凭据或许可证服务 |
| AI-Union-Platform | 通过版本化公开契约使用核心的私有商业平台；不预设组织业务、结构或经营方法 |
| ai-union-corp | 建设和运营上述产品的具体公司场景；代码开发不是所有 AU 的资格条件 |

单 Agent 叶子 AU、多成员 AU、组合 AU 共享组织概念和适用契约。组织规模不决定进程规模；治理/授权、工作协作、执行部署三种关系分别建模。Human-free 是授权和资源内无需日常人工接力的运行目标，不是排除人类参与的资格审查。

七项特征 Continuous、Efficient、Proactive、Persistent、Recursively Composable、Self-improving、Human-free 均须有明确需求和证据路径。阶段交付可声明部分能力，不能靠取消目标、减少责任或改名来提高完成度。

## 3. 用户、责任与主要旅程

核心自带基础认证、AU 权限和审计。宿主维护者、核心账户操作人、AU 初始治理主体/最终决定方、成员、平台商业客户和外部接收方是不同角色。付款、托管、登录或角色显示名都不自动产生 AU 治理权。默认创建者成为初始治理主体必须有受信身份绑定和采用依据；旧记录没有该依据时不能补造。

| 旅程 | 可观察的正常结果 | 关键失败与恢复 |
| --- | --- | --- |
| J01 独立安装与进入 | 无私有平台账户也能安装核心，首次认领、固定地址登录、退出/改密及维护恢复可用 | 配置/依赖/端口失败可诊断；重新认领不接管已有治理身份或删除业务历史 |
| J02 创建与准备 | 保存目标、有效治理根、AU Charter 和有限资源；重新打开同一 AU | 重复请求返回原结果；治理未绑定不得自主行动；不兼容旧记录明确限制，不隐式迁移 |
| J03 真实工作 | 配置合法模型/工具后，单 Agent 或按目标形成的团队推进工作、使用依赖资料并交付 | 保存不调用模型；能力/授权不足可解释；失败不解除责任，局部受阻不拖停独立工作 |
| J04 反馈与持续行动 | 验收成果，吸收反馈或环境变化，形成并执行下一步；无逐步人工派工 | 重复事件不重复采用；旧事实纠正后复查相关活动工作；无意义轮询不空转花费 |
| J05 治理与恢复 | 有效修章、撤权、交接、暂停、唤醒及故障后责任连续 | 旧执行不能继续取得新授权；未知副作用先核对；保留事项形成持久关注事项 |
| J06 更新与维护 | 指定候选构建可安装、诊断、备份、恢复，并在声明兼容范围内升级/回滚 | 代码回滚不等于业务回滚；不可逆变化事先说明；新旧机制不重复派发 |
| J07 组合与协作 | 两个 AU 接受并履行承诺，组合 AU 对外提供相同契约 | 发送不等于接受；撤权/失联/争议/部分完成可追踪，内部资料不因组合全部共享 |

| Q-04 真实运行与发布参数 | 目标环境、profile、真实样本、预算、观察窗口、容量和维护人由实际资源决定 | 进入对应真实验收前明确；不从旧机器、账号或检查数推定可用 |
| Q-05 许可与发布 | 开源方向已确定；具体许可证与发布/仓库可见性操作尚未选择 | 公开许可或发布前明确；不妨碍本次设计、工程实现和独立性验证 |

具体结构、技术选型、预算数值不是由宪章图示直接指定。工程负责人可在已确认义务内选择并记录；改变义务、治理权或授权范围才回到项目治理决定。

S02 的有界配置/真实只读资料往返按 [精确契约](../specs/053-union-rewrite/s02-contract.md)实施：独立核心用户提交自己的 API 凭据或使用本 AU 预授 grant，验证执行也保留完整责任/资源/定义版本。S02 实现和真实 profile 必须分别取证；其他 profile 与任意目标工作由 S09/S03 承接，不把全部模型能力作为一张卡的隐含前置。

## 7. 验收层次与交付

- **S00需求/设计检查点**：原文及采用记录可核对，40条及子条款无遗漏，PRD/ADR/切片/AGENTS/看板一致，首个实施任务有精确契约，审阅和Git交接完成。
- **工程切片**：严格TDD的有意义RED→最小GREEN→REFACTOR，现有正确行为保留回归；接口/持久化/用户流程贯通并独立复核必要权限/费用。
- **真实能力**：指定模型/工具/主机真实往返、成果和反馈；单Agent与多成员分别取证，C系列启用时另验组合；每profile声明对应实际证据。
- **用户闭环**：无需人工逐步搬运/派工，交付可读成果、接收验收反馈并落实下一次改变；分类记录人工参与、失败、费用与不确定性。
- **发布与持续运行**：无私有平台依赖的独立安装与真实工作；窗口内重复交付、空闲/主动观察、唤醒、局部故障、重启、额度、升级/回滚与恢复通过。

S01 已有稳定核心主体、准备态创建/重开及兼容隔离的[受控实现证据](../evidence/056-s01-core-creation/README.md)。S05 的本地治理、修章/继任/退出和内部记录责任闭环见 [057](../evidence/057-s05-governance/README.md)；人类受控操作不代表 AI 自治或真实业务治理，完整治理、发布及持续运行仍有后续验收。`management/project.json`仍是任务、成熟度和验收唯一主账；[在线Kanban约定](../management/KANBAN.md)提供同一U任务的协作视图，不形成自动双向状态源。
