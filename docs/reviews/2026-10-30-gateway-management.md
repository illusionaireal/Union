日期：2026-10-30。复核角色：gateway_authorization_review（独立于实施者的工程代理）。对象：当前 dev 工作区的 027 第一批实现；未审阅或批准尚未实现的 Docker 启停、升级、备份和恢复。

## 结论

通过本批受控采用复核。平台权限隔离、同源传输和无凭据探测的独立实测通过；初审发现的 R1 已修复并独立复验，AU 目录也已收窄。当前未发现阻止第一批受控采用的问题。本记录不证明真实 New API、真实模型工具往返或持久部署通过。

## 独立实测

使用全新临时 Console、实际本地 HTTP Server 及回环状态接口替身，不读取用户凭据、不调用真实模型。21 项行为探测通过：

- 普通全局 board、observer、组织受限 board 均不能写网关或读取平台操作回执。
- 宿主拒绝将平台权限授予 observer 或组织受限会话；普通一次性启动 ticket 不提权，显式管理员 ticket 正确保留能力。
- 经授权保存成功；同请求及同参数返回原回执；相同请求 ID 更换参数被拒绝。
- 普通 board 无组织参数不能读取平台目录；无权组织参数不能绕过组织范围检查。
- 实际 HTTP 跨来源管理员写入返回 403；同源普通 board 写入返回 403；同源平台管理员写入成功。
- 实际探测仅请求 `/api/status`，不发送 Authorization、Cookie 或代理凭据给目标；302 不被跟随且记为不可确认可用。

静态核查还确认：检测结果按网关 revision 及最新 probe ID 应用，旧目标/旧请求结果不覆盖新登记；网关来源按 AU 模型连接版本保存，修改/解除登记不自动重定向已有连接或继承其他 AU 的令牌。平台权限不进入 Agent 上下文，页面隐藏不是授权依据。

## R1：检测作业资源边界（已关闭）

`probe()` 的 2 秒 socket timeout 不是总体时限。回环服务每 0.35 秒发一个字节并持续 10 次，检测实际耗时 3.51 秒；持续发送可使 `read(65537)` 长时间占住非 daemon 作业。当前每次提交检测又可新建线程，宿主 `close()` 只有 10 秒 join，不能限制前述总持续时间。

修复：探测在固定 Python 模块子进程运行，配置以 stdin JSON 传入，不使用 shell、不接受任意命令或宿主路径；父进程 `subprocess.run(timeout=4)` 在超时后终止并回收子进程，覆盖 DNS 与慢速响应等待。每个网关最多一个 accepted 检测，全局最多八个。

独立复验：回环服务每 0.2 秒发送一字节，原定持续八秒；探测于 4.01 秒返回 unavailable，未等待完整滴流。另使用九个登记和受控阻塞探测验证：前八个受理，第九个被拒为繁忙；释放后全部作业可 join。单实例在途互斥、旧 revision 隔离和宿主中断 unknown 恢复亦由下述回归通过。
