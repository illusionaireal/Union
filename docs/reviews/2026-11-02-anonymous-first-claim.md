# 2026-11-02：匿名首次认领管理员变更的独立复核

本轮改动触及账号与权限边界，按仓库规则需另一工程角色的独立复核。复核由独立只读代理完成：先读 NAS checkout 的实际代码与运行库，再给结论；未修改文件、未重启服务、未提交或推送。复核对象是 U-057 的实现（`ai_union/identity.py`、`ai_union/server.py`、`web/console/src/pages/Identity.tsx`、`tests/test_identity*.py`、`scripts/reset_owner.py`）。

## 复核结论

有条件上线。单点校验与并发语义可靠，但两处需要先改：

1. **匿名认领直接写入 `platform_admin=True`**，绕过宿主既有的显式平台管理开关（`server.py` 的 `--enable-gateway-management` 语义）。该标志实际覆盖网关宿主凭据引用、网关连接管理和订阅/账号后端授权。
2. **领取窗口不是“首次启动”，而是“账号为空就一直开着”**。线上库在复核时 `owner_account=0`，但已有 1 个组织、3 条订阅原生尝试和部分命令回执，因此窗口内被他人认领会同时暴露现有数据。

## 处置

- 平台管理改为宿主显式开关：匿名认领只有在 `UNION_FIRST_CLAIM_PLATFORM_ADMIN=1` 时获得 `platform_admin`，默认不加。本 NAS 部署由宿主显式开启（用户要求保留平台管理能力）。
- `can_setup` 与后端规则对齐：只有未设置账号、且当前会话为空或为无组织限制的 board 时才提示设置，避免 observer 或组织 board 看到必然失败的按钮。
- 带 cookie 但无效/过期不再落入匿名路径，必须显式无会话才可首次认领，避免授权语义随 cookie 状态漂移。
- 重置脚本补：库结构校验（缺 `owner_account` 直接拒绝）、重置前 SQLite 备份（0600）、占用/损坏的明确错误、宿主真实路径示例、重置后窗口重新开放提示。
- 补测试：匿名双请求并发只产生一个账号、过期 cookie 不能走匿名路径、平台管理开关开/关、重置脚本试运行/备份/异构库拒绝。
- 领取窗口持续开放未改：这是用户明确选择的产品行为（“谁先访问谁设置，失败就重置”），在单宿主 LAN 部署下由重置入口兜底，本轮不引入时间窗或来源限制。

## 复核指出的遗留问题（本轮不关闭）

- 既有 `install/run_frontend.py` 每 300 秒向私有 `access.json` 写入带 `platform_admin=True` 的一次性票据，等价于一条不依赖账号密码的管理员通道。这在本轮之前就存在，不是本次引入；账号建立后是否停止下发平台管理员票据，留给后续任务。
- 匿名认领没有来源记录或限速，事后只能从“已配置 + 未知账号”判断有人认领，无法归因。
- 复核未验证：真实浏览器领取流程、真实并发压测、NAS 重启后的窗口行为、容器重启后 `platform_admin` 开关的实际生效。

## 边界

本复核是代码与授权边界的独立审阅，不等于部署验收。真实模型调用、订阅最终登录、组织持续运营仍按各自证据单独验收；本轮模型调用为 0。
