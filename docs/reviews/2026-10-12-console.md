## 发现与修复复验

### R1：作业线程启动失败后回执永久受理中（P2，已修复）

复核时通过注入 `Thread.start()` 的 `RuntimeError` 复现：start 命令已经提交 `accepted` 回执，线程未启动，重复同一请求仍返回 `accepted`、调用数为 0；未启动线程却已经进入 jobs，正常关闭再抛出 `cannot join thread before it is started`。

实现角色修复为在线程成功启动后才登记 job 和移交派发锁；启动阶段的 `RuntimeError` / `OSError` 保存脱敏的终态拒绝回执与暂停意图，并释放派发锁。同一请求跨重启保持原回执，不自动派发；新的显式请求可在宿主恢复后启动。

独立复验 `test_thread_start_failure_is_durable_and_does_not_dispatch_or_leak_lock` 通过，覆盖 0 次派发、暂停、无未启动 job、锁可再次取得、关闭与重启、原 ID 不重放，以及新的显式请求可执行。相关慢执行暂停、并行重复命令、遗留运行不重放三项回归也通过。R1 已关闭。

## 授权、事务与恢复检查

- 身份来自宿主内存会话，浏览器不能提交 actor、任意存储路径或董事会密钥。组织 ID 在访问存储前进行格式、会话范围与目录登记检查；观察者直接调用写接口也被拒绝。
- HTTP 限制 loopback 监听、精确 Host、同源写入 Origin 与 Fetch Metadata；一次性启动票据交换为 HttpOnly / SameSite=Strict 会话。启动材料和请求内容不进入访问日志。这里仍以操作系统账户和本机文件访问为受信边界。
- 非创建命令的请求参数绑定、组织版本检查、业务变更和回执写入共用 SQLite 外层事务。嵌套 SAVEPOINT 使业务失败回滚后仍能保存拒绝回执。并发重复事件只提交一次；已存在 ID 的不同参数被拒绝。
- start、资源调整、修章和核对复用 CLI 的派发锁；修章仍检查旧章程及宿主保存的董事会凭据。资源更新不删用量，网页不能声明未经支持的金额硬上限。
- 暂停写持久意图，调用预约在自己的事务内再次检查暂停，覆盖选择工作与预约之间的竞态。已在途执行等回执；暂停并不证明远程取消。
- unknown 保留调用占用，start 拒绝重派；只有指定 unknown run 可核对。遗留 running 先显示活性未确认，取得派发锁后的显式启动才恢复为 unknown，不自动再次执行。
- 快照使用只读连接与一次数据库事务，不消费事件、恢复运行或预约调用。状态、执行、计数和回执保持同次读取；同版本新增事件或预约仍可观察。成果读取限制在资产目录并校验 SHA-256。
- 观察投影不返回董事会摘要、密钥、完整执行工作包、资产路径或私有执行日志。宿主失败事件、工作摘要和作业回执使用适合浏览器的摘要；组织主动提交的内容仍作为组织数据展示。
