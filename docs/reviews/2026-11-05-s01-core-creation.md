## 身份与持久化边界

最终结论：四项发现均修复并复验，已审后端范围无剩余 P1/P2。独立执行 **47 项测试，54.082 秒，OK，无跳过**，覆盖创建、故障恢复、发布兼容、旧目录完整性、HTTP、CLI/workspace 和保留句柄隔离。

| 发现与原失败 | 修复所有者与独立复验 |
| --- | --- |
| 创建分配目录可经父级链接逃逸，见 `red-core-review.log` | `adapters/au_catalog.py` 在存储调用前核对分配。真实 symlink、Windows junction 对新旧协议均拒绝，外部没有创建文件；正常目录两协议成功 |
| V1 创建采用记录未充分关联原意图，见 `red-core-review.log` | `core_au_store.py` 与 Console 生命周期解析核对请求 ID、时间和初始内容。单独篡改任一项后读取、列表、关闭及冷启动均拒绝并保留损坏字节；恢复原值后重开原 AU |
| 发布兼容检查接受不完整当前 schema，见 `red-release-auth-review.log` | `release_package.py` 复用身份 schema 解析。缺收据列、负数或文本 revision 均在代码指针切换前拒绝且数据库不变；仓库外执行可导入同包解析器 |
| 初次认证遭遇真实 catalog 排他锁时未给出类型化存储错误，见 `red-release-auth-review.log` | `server.py` 覆盖初次认证存储异常。锁定期间 POST 返回 503 `storage_unavailable`，无创建意图或目录；释放锁后正常创建成功 |

升级回执的投影写入失败与 schema marker 缺损另有真实 RED/GREEN，保存于 056；升级事实在 catalog 事务中持久化，投影失败后重跑可恢复回执，不重发 principal。这里不宣称抵抗恶意宿主篡改或任意并发文件替换。

## 前端身份、回执与恢复

最终结论：当前已审前端范围没有未修复的阻断问题，建议进入最终验收，信心 B。固定 Node 24.19.0 下独立正式聚焦测试 **21/21**、隔离反例及合法控制样本 **9/9** 通过。实际 Chrome 对正常名称和合法 200 字符名称在 **1440/1024/390/320px** 均通过局部内容边界检查。

| 发现与原失败 | 修复所有者与复验结果 |
| --- | --- |
| 错误 POST 回执可被采用，跨主体提交未拦截 | `CommandForm.tsx` 校验原请求 ID/kind/组织，提交前核对最新主体；同 principal 会话续期合法控制样本保留 |
| 旧主体的迟到回执污染新主体导航 | `CommandProvider.tsx` 采用回执时核对挂载状态、当前 principal 与服务实例，旧响应不改变新账号路由 |
| 同主体会话轮换重建界面并丢失输入 | `Identity.tsx` 以稳定 principal 作为 V1 身份边界，合法续期保留草稿和焦点 |
| unknown 查询失败被隐藏，身份预检取消后仍 POST | 可见结果区展示查询错误；预检中的取消阻止请求，处理中字段/按钮受控。对应真实失败见 `red-core-ui-review-expanded.log`、`red-core-preflight-cancel.log` |
| 合法长名称在窄屏被截断 | `PreparedAU.css` 保留完整换行；真实浏览器失败见 `red-core-name-browser.log`，最终四种宽度局部和整体验证均通过 |

这些是既有 S01 契约下的实施偏差，修复没有添加 legacy 自动回退或扩大准备态能力。创建字段、回执匹配、身份边界和准备态展示各自有明确所有者。
