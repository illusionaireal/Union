# 030 外部开发调度器：独立工程权限复核

日期：2026-11-01。复核者：`orchestrator_authority_review`，独立于实现上下文的外部工程角色。依据：用户交接文档第 7.5 节及 AGENTS 对权限实现的独立复核要求。范围仅为本轮 `ops/dev-orchestrator/`、对应规格及新增机制测试；未审查、归属或提交用户原有工作区变更。

## 结论与采用范围

允许在独立目录部署**默认关闭的工具及诊断入口**，使用无认证的固定安装、验证容器继续取得工程证据。当前**不批准注入真实认证、派发真实模型或启用小时开发调度**；不得将此次代码复核写成 E02/E03 真实 Astra/Sol 链路通过。

实现者报告：NAS kernel 4.4 的实际 Codex Linux 沙箱探测返回 `bwrap` 无法创建 user namespace；独立设备登录请求得到官方 HTTP 403，未注入真实认证。本复核未直接重跑这些远端命令；实际结果应以本轮部署诊断原始日志为依据。不得通过扩大宿主权限、挂载 Docker socket、移除 Codex 沙箱或改为 danger-full-access 来绕过。

宿主示例配置的 `enabled=false`、`max_calls=0`、`sandbox_verified=false`、`credentials_isolation_verified=false`、`model_access_verified=false` 形成关闭边界。控制器 `invoke` 与 broker 模型分支分别检查沙箱和凭据隔离标志，当前必须保持为 false。未来修改这些宿主标志前，须有可执行沙箱、工具读取假凭据被拒、仓库测试无法取得认证、无秘密外传的实际证据与后续复核；路径变更和只读挂载本身不构成凭据隔离证明。

## 初审发现及当前修复

1. 初版 Worker/Validator 可写 `.git`，存在修改宿主 Git 配置、索引和版本依据的风险。最新版对所有角色嵌套只读挂载 `/repo/.git`，宿主 Git 禁用 hooks 和 fsmonitor；日常角色不挂载 Docker socket、控制器状态及宿主 root。
2. 初版 Planner 可以通过 `requires_independent_authority_review=false` 豁免复核。最新版由宿主 `non_authority_tasks` 和绑定基准 SHA 的 `independent_reviews` 决定；模型不能自行豁免。
3. 初版锁绑定各自状态目录，相同仓库可取得不同锁。最新版锁位于仓库 `.git/union-dev.lock`；broker 还检查仓库身份标签对应的运行容器及未核对预约。
4. 初版文件证据仅记录内容哈希，门禁还会覆写已审阅 patch。最新版记录文件模式，比较完整 diff，并使用 `snapshot(write=False)` 检查，保留原始证据。
5. 初版日志截取最后 20,000 行，期限按每次调用重置。最新版读取完整 Docker 日志，以整轮创建时间检查期限，并记录无新输出告警；安静不被认定为请求结束。
6. 初版接受后缺少主账收口。最新版新增 `claim_task`，先检查 WIP、如实记录实际 owner/started_at 再执行；`finalize` 更新目标任务和脱敏报告，固定无认证、无网络容器生成/检查 PROJECT/TASKS，限定后续提交文件。新增完整受控失败→修正→接受→代码和主账两次精确本地提交用例通过；此为受控机制验证，不能据此宣称真实 E09 已通过。

## 浏览器内网例外复核

最新版仅对固定 Validator argv `npm run test:browser`、`npm run test:gateways` 使用 `union-dev-validation`；其他验证、Chromium 烟雾及主账生成保持 `network=none`。broker 使用宿主测试 profile 选择 argv，模型不能提交任意命令/网络名。最终代码在启用例外前核验 `Internal=true`、`Driver=bridge`、`EnableIPv6=false`、`com.docker.network.bridge.inhibit_ipv4=true`、网络 ID 等于宿主安装记录，并拒绝已有 endpoint 的网络；不发布端口、不挂认证或 Docker socket。安装代码创建专用小子网、记录网络 ID，不复用默认/生产网桥。

据实现者现场诊断，loopback-only 令 Chromium `navigator.onLine=false`，本地 API 虽实际返回 200，原浏览器用例仍判为断开；此次改动在测试网络条件上修复这一环境差异，没有放宽产品断言。实现者报告 NAS SSH 和外网地址实际连接失败，专用网络没有接入生产容器。这些远端连接探测由实现者运行，本复核验证了代码选择和配置检查，没有独立重跑探测。

该例外不改变“允许默认关闭部署”的结论，也不解决 Codex user namespace 或认证隔离阻塞。不能把内网网卡存在写成公网访问许可，也不能将若干目标连接失败扩大成所有宿主地址、端口或协议均不可达的证明。最终检查已覆盖驱动、IPv6、已记录网络身份及派发前空端点；后续仍须维持专用网络并禁止外部管理员在作业运行中把生产容器接入，同一时刻配置核验不构成对宿主管理员后续动作的限制。

## 仍需完成的缺口

- **真实认证隔离仍阻断。** `/auth/auth.json` 和 `/run/union/codex/auth.json` 与工具进程同 UID；现有容器只读挂载不证明工具不可读取。目前靠前置门禁禁止派发，不能开启后再验证。
- **真实完整链与 finalize 故障恢复仍未验收。** 完整受控接受/修正循环和主账闭环已有通过用例，真实模型链、主账生成失败或两个提交之间中断的恢复仍缺独立场景。代码提交发生于最终主账提交之前，中断后应核对已生成提交，不能自动重复阶段或宣称任务已完整关闭。
- **长日志传输上限。** broker 已去掉 tail，但控制器和维护客户端仍以单行 JSON、最多 16,000,001 字节读取响应。超过上限将解析失败并保留未知占用；需要日志文件/分块传输机制，不能静默丢弃完整证据。
- **运行期限不是容器强制停止。** 整轮到限后控制器停止观察并要求核对，原容器可能继续运行；这保护未知执行不盲目重放，但不能宣称已经强制限制四小时计算用量。
- **保留策略未实现。** 原容器和全量日志持续保留，尚无磁盘限额、保留期及经过核对后的清理流程。上线前需要明确策略，清理不能删除未核对作业的唯一证据。
- **缺失容器不能单独证明未执行。** `resolve_not_started` 查询当前容器不存在，不能排除原容器曾运行后被外部删除。该维护动作必须结合原始身份、日志/事件和人工核对，不得据此自动重发外部请求。

本次结论是有条件的默认关闭部署复核，不是生产采用、真实模型权限、额度授权或公司自主运营验收。
