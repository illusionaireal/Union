# 小说公司首版体验

UNION——一家开箱即用的 AI 公司。当前试验让用户提供目标和预算，在董事会章程下完成同一本小说的三个经营周期。

## 先看效果

在 `dev` 分支，从仓库根目录启动：

```sh
git switch dev
git pull --ff-only origin dev
npm ci --ignore-scripts
npm start -- --root .union/novel-demo --novel-demo --open
```

首次启动创建一个独立的、明确标识为模拟的公司，自动执行固定演示脚本。总览提供三章正文、模拟订阅与收支、第二章低订阅反馈、第三章调整任务及其成果。重复启动复用同一演示，不重复记账。此路径不调用模型，不验证模型自组织能力；小说正文是仓库内演示样稿。

需要 Node 24.19.0、Python 3.11+；Windows 沿用 `npm start`，由启动器选择 Python。

## 使用自己的真实模型

```sh
npm start -- --root .union/novel-real --open
```

1. 总览 → **新建组织** → 创建类型选择 **小说公司 · 三周期首版**。填写公司名称、经营目标、启动模拟预算、模型输入/输出单价，查看并采用默认章程。
2. **模型与 API → 添加 API 连接**。填写 API 根地址或完整 `/chat/completions` 地址、模型 ID、API Key，选择供应商支持的输出上限字段。模型须支持工具调用，无需选择 JSON 输出模式。保存同时绑定默认连接，不调用模型。
3. **测试连接**：确认一次普通对话调用，沿用连接配置的输出上限及超时。推理也可能消耗输出额度。成功回执显示在模型页，计入额度和费用估算；它只证明普通对话连通，组织初始化还需工具调用成功。
4. 回到**总览 → 启动／继续**，默认选中 API，确认本次有限调用。默认公司累计上限 32 次、单次超时 180 秒、运行最多 30 步；实际供应商最大输出默认 8192 token，可在配置时调整。
5. 观察成员与岗位、工作依赖、三章正文、反馈复盘和账本。三轮完成后本次试验停止，等待审读。若达到步数但尚未完成，可在剩余调用额度内继续。

岗位、成员、题材、设定、创作和审核任务由模型提出。宿主提供投稿和复盘动作，校验授权、正文存在、章节顺序、当前成果版本及执行时间。第二章固定低订阅反馈必须进入后续任务；第三章必须来自反馈决定后实际交付的成果。组织无法修改平台规则或直接填写收入。

API Key 只保存在组织私有配置中；网页预览遮蔽，不写入浏览器持久存储、命令载荷、工作包、账本或回执。部署方式仍为本机受信工作台。

## 数据含义

| 数据 | 来源与范围 |
| --- | --- |
| 启动预算 | 模拟经营试验的期初余额，CNY 整数分；不是实际转入资金 |
| 模拟订阅 | 平台 v1 固定返回 12、2、8，第二周期为受控负面反馈；不代表内容质量或市场需求 |
| 模拟收入 | 每订阅 30 分；三个周期分别 360、60、240 分 |
| 模拟费用 | 每周期服务器 20 分；模拟税费为收入的 6%，每笔向上取整；不是实际适用税率或税务计算 |
| 模型用量 | 实际 API 回执的输入、输出 token；Fixture/本地 HTTP 替身明确标为模拟用量 |
| 模型费用 | 按创建时配置的每百万 token 单价估算，每次调用向上取整至分；缓存输入暂按普通输入单价估算 |
| 预算控制 | 估算余额到限停止新派发；单次调用可能越过阈值，不是供应商账单的精确硬上限 |

表单默认输入 100 分/百万、输出 500 分/百万是示例单价，请按实际供应商填写。连接测试、失败调用若有用量也计入估算；缺失用量保留未知并暂停新调用，不能填作零成本。

## 最小恢复

运行失败时，先查看总览、模型页回执或“执行与资源”的错误提示。HTTP 400 会提示被拒绝的已识别参数；输出截断提示调整最大输出；决定校验失败提示具体的已识别规则。提示由宿主固定文本生成，供应商错误正文不会回显。修改配置后仍需手动重测或继续；未知结果、未知用量按下面步骤核对。老版本历史失败未保存分类时仍显示通用提示。

- 已知失败保留任务、调用和回执。已收到的组织提议若未调用工具或参数校验失败，本次剩余额度内允许一次带原因的修正，每次单独记调用和用量；HTTP 故障、拒绝、截断及未知结果不自动重发。
- 缺失用量：设置页 **核对缺失模型用量**，依据供应商记录填写输入/输出 token 和证据。确实未计费可填 0，但必须有依据。补录标为“董事会核对用量”，原供应商回执不变；同一笔不能重复结算。
- 结果未知：先用现有“核对未知执行”处理，再补录缺失费用。未知远程结果不能盲目重派。
- 预算或调用额度不足停止派发并保留进度。调用次数可经现有资源入口调整；首版不提供追加模拟资金或改价入口，需要扩大经营预算时新建试验。

## 验收

工程机制、真实模型能力和作品质量分别判断。

- 工程：一次启动持续三周期、同一本小说三章、投稿/结算幂等、反馈到决定再到实际任务/成果、持久恢复及权限有效。
- 真实模型：用新公司和实际供应商运行，保留所有成功与失败；本地 HTTP 替身不能冒充真实调用。
- 人工审读：三章设定一致、情节衔接、每章有推进；第二轮反馈后的改动真实落实到正文。程序不会因为模拟订阅数上涨就自动判定质量提升。

自动化验证：

```sh
python3 -m unittest discover -v
npm run check
python3 scripts/check_console_start.py
npm run test:browser
npm run test:novel
```

浏览器检查需要 Playwright Chromium；可用 `UNION_CHROMIUM_PATH` 指定已安装的浏览器，`UNION_PYTHON` 指定 Python。新证据在 [006 验证记录](../evidence/006-novel-company/README.md)。当前真实供应商试跑尚未完成，真实盈利与市场需求没有证据。
