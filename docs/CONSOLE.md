# 本地组织工作台

当前界面提供八页导航。**模型 API 入口在左侧“模型与 API”**，所有通用组织均可使用。先创建公司，再点击“添加 API 连接”填写地址、API Key、模型 ID，预览并保存。连接卡可编辑、设为默认、取消默认和确认一次连接测试。保存不会调用模型；API Key 不回显，编辑留空保留原值。完成后在公司总览选择有限运行。旧小说指南中的“组织设置配置 API”入口由独立模型页接续。

更新：2026-10-18。使用 Node 24.19.0 和 Python 3.11+；启动器会在项目 `.venv` 安装固定 Harness 依赖。从仓库根目录首次安装，然后一条命令构建并启动：

```sh
npm ci --ignore-scripts
npm start -- --root .union/console --port 8766 --open
```

Linux 默认 `python3`，Windows 默认 `python`，可设置 `UNION_PYTHON`。依赖与构建就绪后，可直接使用项目解释器运行 `.venv/bin/python -m ai_union.server --open`（Windows 用 `.venv\Scripts\python.exe`）。服务只监听本机，`--open` 打开一次性发起人链接；默认仅配置 fixture，创建不会自动运行。

正式前端是 `web/console/` 的 React + TypeScript + Vite 工程，构建目录由 Python 同源提供。八个页面支持直接访问、刷新和前进后退；架构及开发模式见 [FRONTEND.md](FRONTEND.md)。独立单 HTML 原型、旧工作台和报告已按用户要求删除；不再提供其生成入口。历史证据保留，见 [退役说明](site.md)。

## 本机会话

服务启动时将发起人和观察者的链接写到私有目录中的 `local-access.json`。链接 10 分钟有效且只能交换一次；使用后从地址栏移除，服务设置 HttpOnly、SameSite=Strict Cookie，会话最多 8 小时。观察者可查看和下载，直接调用写接口也被拒绝。

服务重启使旧会话失效；使用新生成的本机链接重新连接。若不带 `--open`，在本机读取 `local-access.json` 后打开相应链接。启动链接属于临时访问凭据，不上传、不贴到公共页面。正式董事会密钥始终保存在组织目录，不传到浏览器。

这是受信本机管理员的工具，不是远程账号平台。Windows 使用当前用户的文件访问权限；`chmod(0600)` 不是 Windows ACL 隔离。不要将端口代理为公开服务。

## 创建与运行

1. “新建组织”填写名称、目标、采用人、章程和有限资源；展开规则字段可查看所有受支持条款。预览后确认采用，得到独立组织目录。
2. “启动／继续”选择 fixture 和有限步数。默认样例的完整闭环使用 6 次调用，产生两成员、三项工作和三份成果，之后等待新事件。样例是确定性测试，不代表模型自组织。
3. 工作详情链接依赖、成员、成果与决定；成果打开和下载都读取实际文件并校验 SHA-256。工作台每 4 秒自动读取，手动刷新立即读取；网页读取不派发工作。
4. “暂停派发”持久保存停止意图。有在途调用时先显示等待回执；结束后才显示已暂停。暂停不会推断远程取消，后续继续仍受原额度约束。
5. 在组织设置中调整资源、修章或核对。运行锁被占用时管理修改明确拒绝；资源上限不能低于累计占用。修章按旧章程权限与当前状态版本生效。

有限运行作业不会因服务重启自动续跑。启动入口取得原 CLI 互斥锁后检查遗留执行；遗留 `running` 转为 `unknown` 并受阻，不重复派发。读取只显示“活性未确认”，不会自行恢复。只有有效心跳、持锁与该次执行的宿主标识相匹配，才显示正常执行。

未知结果必须填写核对依据，选择确认未执行或放弃。核对不退款、不自动重试、不自动导入远程成果。CLI 与网页共用组织数据库及运行锁；CLI 也遵守已保存的暂停意图。

## 请求与存储

浏览器为每次确认提交生成请求 ID。命令完整参数与该 ID 绑定；重复同一请求查询原结果，不重复操作。版本冲突保留表单输入，读取新状态后重新预览。请求超时先查询原回执；刷新页面不会重新 POST，晚到的请求错误不会覆盖已确认的成功回执。

服务根目录含 `console.sqlite3` 和 `organizations/`。每个组织目录保存 `state.sqlite3`、`board.key`、成果以及私有执行记录；目录由宿主分配，浏览器不能传任意路径。服务能保留多个独立本地组织，当前视图始终只读选中组织，不构成多租户托管。

创建涉及目录与数据库，不能假设跨文件事务。先持久登记分配目录，存储中断则保留原请求为 unknown，不自动再次创建。管理员需核对该创建记录与分配目录；本轮不提供自动修复创建目录的按钮。

快照在同一个只读 SQLite 事务内包含状态、调用占用、执行、事件、决定和命令回执。服务实例、快照序号及浏览器请求序列共同阻止旧响应回退；新增事件或决定预约即使不增加组织版本也会显示。事件与决定按每类 50 条分页，最近 30 条命令回执显示在设置页；具体请求可按 ID 查询。

## 真实执行与范围

### 在管理后台设置模型

进入“组织设置 → 模型设置 → 设置默认模型”，填写 Codex 支持的模型 ID 和修改理由，预览后保存。设置按组织持久保存；留空恢复 CLI 默认。保存不会调用模型或验证模型可用性，也不会启用真实执行器。

选择 Codex 启动时，“本次模型”自动填入组织默认值，可以只覆盖本次运行。提交回执保留解析后的 `requested_model`，之后改默认值或查询旧回执不会改变已有作业的模型。运行中先暂停并等待回执再修改；观察者只能查看。

CLI 的 `run`／`watch` 省略 `--model` 时也使用该组织保存的默认值；显式 `--model` 优先。默认值在取得派发锁后读取，防止与网页设置交错。这里配置的是模型名称，不是 API 地址或密钥；现有登录和宿主启用要求仍适用。

只有宿主显式传入 `--enable-codex`，网页才显示真实执行器；每次真实启动还必须明确接受有限调用费用未知。当前验收全部为 fixture 和接口替身，真实模型调用为 0。本轮未核验本机真实 Codex 的登录、沙箱或 token 回执；Windows 的进程兼容测试不代表真实执行器已验收。

有限真实运行应使用新组织与明确的调用额度，保留成功和失败。真实发布渠道、市场反馈、收入与部署继续独立验收；本轮没有这些证据。
